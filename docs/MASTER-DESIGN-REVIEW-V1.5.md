## 一、产品的本质

**不是通用文生视频网页，也不是 AI Chat 套壳。**

它应当是面向个人创作者的**专业、可持续、轻操作的智能影视工作室**：以好故事、人物、导演、视听节奏、连续性和成片品质为目标，系统管理真实状态、媒资、模型生成、返工和版本；专业 LLM 在六区深度协作，创作者把控艺术和重要授权。

**六区同级**：前期创作（可深度改剧本）→资产设计→导演创作（创建正式 Shot）→分镜和生成规划（完善同一 Shot、规划 Clip）→生成制作（真实 Run/Take）→审片成片（选 Take、轻剪、Render）。真实工作可以往返，不以强制关卡串成僵硬流程。

## 二、已确认的正式资产标准

| 类型 | 已批准产品形式 | 不能被偷偷修改成 |
|---|---|---|
| **人物** | **每个 Character Look 一张完整 2:3 竖版 2×2 宫格**：正面头肩、90°侧脸、无头正面全身服装、完整背面全身 | 四个必须入库的拆分参考单图 |
| **场景** | **一个场所/环境状态一张完整上 1 下 3 图板**：上方大主视角，下方反向、行动区、侧向补盲 | 四格等大 2×2 或多个无关地点 |
| **重要道具** | **一张完整上 1 下 3 图板**：主图大、下面结构反面/剧情关键细节/尺度功能（按类型调整）；普通陈设纳入场景 | 所有杯子/路牌强制建关键道具，或四张独立正式图片 |
| **角色声音** | Voice Identity 含**独立基准语速**，导演与分镜可按场/句调整表演语速及独立停顿；主要人物建议基准样音，环境/关键声音轻量管理 | 只用文字“温柔女声”，语速被情绪标签吞掉 |

**图板形式批准 ≠ 图片模型真实多角度一致性验收通过 ≠ 视频模型一定理解图板**；所有出图比例、像素、跨格逻辑、H3 真正效果另按样张确认。

## 三、已查到的真实模型接入差异

- **Darl 自部署 MiniMax-H3**：通过 `POST /v1/videos` + `content[]`；公开接口文档写有 4–15 秒、最多九张参考图、帧控制与多模态参考互斥、可取消与**二次采样**等。
- **Darl RunningHub H3**：模型名 `runninghub-minimax-h3`，需要先上传媒体并取得网关素材 ID，最多六张参考图片；文档未提供取消、独立二次采样或原生续接接口。
- **Darl GPT Image 2**：图片生成返回 `data[].b64_json`，必须解码并保存在真正可用的 MediaFile 中；不能把文本 Prompt 或一次返回结果当成正式长期图片。
- **重要空缺**：用户报告**已实现原生 H3 Motion Context 续接**，但现在能读到的公开网关接口没有该能力的可执行父上下文调用合同。**二次采样/上段末帧/视频参考都不等于真续接**，实际新接口与一条证据需后续核实。

上述是**2026-10-10 的公开文档级核对，未做本项目实际认证/付费测试**。参考：[接口核验报告](integrations/H3-ROUTE-CAPABILITY-AUDIT-2026-10-10.md)。

## 四、电影生成生产合同（第 3→4→5 区）

1. 剧本 Scene/Beat 与导演选择，形成唯一 ID 的 Director Shot，保护叙事目的、表演、摄影和音画意义。
2. 同一 Shot 在分镜区被具体化为动作、原文对白、语速、停顿、声音事件、场景/人物/道具整图参考及进入/退出状态。
3. **Shot 与 Clip 多对多**：一个 12 秒 Clip 可含两个导演 Shot；一个 22 秒不切镜 Shot 可以规划 B1 12 秒 + B2 10 秒，**不能因 15 秒模型上限自动加镜头剪辑点**。
4. 第 5 区先编译**模型无关视听计划**，再用不同类型的 H3 适配器生成确定合法的请求，冻结 Compiled Input / Run 及真实资产版本；费用需授权。
5. DAG 并行执行**无依赖的任务**，B2 类真正续接必须等待指定 B1 父 Take + 实际 Motion Context；父 Take 改选要保留旧分支而不是错误复用。
6. 远端任务完成后下载持久媒体、验证可播放/有声，再建立可审片的 Take；技术成功不等于作品质量通过。

具体合同：[资产就绪](v1.3/11-ASSET-PRODUCTION-READINESS-AND-QA.md)、[导演分镜](v1.3/12-DIRECTOR-SHOT-TO-CLIP-HANDOFF.md)、[生成引擎](v1.3/13-H3-GENERATION-ENGINE-AND-RUN-LIFECYCLE.md)。

## 五、真正的成片交付（第 6 区）

**真实 Take**能够播放比较；对不一致的人脸、空间、道具、音色和语速，留下时间码与上游来源；允许 AI 提出有根据的返工建议。

时间线采用**非破坏性 Segment**，引用某个 Take 的 in/out 区间，支持排序、裁切、必要声画衔接/音量与有限音效；不需要第一版复制专业 NLE。

最终必须**实际生成可播放/可听见的 Render 文件并再次 QC**，源媒体和旧版本保留。

详见 [审片与成片规范](v1.3/14-REVIEW-TIMELINE-FINISHING-V1.md)。

## 六、推荐工程方向（尚未获创作者批准）

**一套桌面优先的模块化 Web 应用 + 持久 Worker + PostgreSQL + 对象存储 + 成熟媒体处理**；模块包括剧本与 AI 协作、资产/声音、导演 Shot、分镜/Clip、路由编译与后台任务、真实审片/时间线/Render。初期不设六个独立微服务/Agent/Kubernetes/复杂工作流基础设施。

**分期交付以真实竖向闭环为优先**，从能编辑剧本和保存媒体开始，逐步实现 Shot/Clip 真实引用→一条授权真实 H3 Run→Take QA→轻时间线→Render，再验证真续接和 80 秒短片全流程。不能先做六个空页面再补功能。

详见 [V1.5 工程路线](v1.5/01-ENGINEERING-ARCHITECTURE-AND-ACCEPTANCE-PLAN.md)。

## 七、现在适合一轮集中审定的 3 个主要问题

| 审定项 | 当前推荐方案 | 若不同意，应改什么 |
|---|---|---|
| **A 产品与六区交接** | 六区共用真实正式事实；第 3 区拥有导演 Shot，第 4 区负责执行计划；资产以已确认整张图板交接 | 改工作边界与设计，不靠后续代码硬拧 |
| **B 生成与成片闭环** | H3 模式严格合法编译、费用授权、Run/Take 历史、真续接单独证明、真实审片/轻量 Render | 调整生产策略/创作自由与失败恢复 |
| **C 工程架构与实施顺序** | 模块化单体 Web + Worker + 媒资存储；先纵向真实闭环，后增强并发与模型覆盖 | 调整部署/技术选型与实际里程碑 |

**不要求**此时逐字段审定 UI 样式、相机数字、Prompt 句法、输入图片像素或每个模型选项。那些被列为可实测/可迭代技术细节，由工程前验证与后续原型决定。

**还有一个实质证据缺口**：用户报告的自部署真续接能力目前没有可读的接口协议；这是后续真续接工程启用前需要的资料，不应阻塞其余已可设计/开发的六区基本闭环。
