# V1.3-02｜第 1 区：专业故事与剧本创作引擎

> **状态：草案，待审定**；日期：2026-10-10  
> 目标：真正提升**故事、人物、情节推进和剧本质量**，而不仅输出一个“可供后续分镜使用”的脚本文档。

## 一、为什么剧本创作是核心生产能力

作品是否吸引观众，往往首先取决于人物要什么、为什么难以得到、做出了什么选择、付出了什么代价，以及观众怎样随着事件改变理解与情感。影视语言可以极大增强这些效果，却不应被用来掩盖故事基础的问题。

因此第 1 区既是早期创作入口，又是整个制作过程随时可以返回的**内容创作中心**。它需要独立、深入、可迭代的专业 AI 剧作能力。

## 二、专业剧作模型（工作要素，不是固定写作公式）

| 关注要素 | 具体问题 | 可能的正式结果 |
|---|---|---|
| 创作命题与类型 | 作品要探讨什么，向谁讲，期望何种观影体验 | Premise / Theme / Audience / Genre 及其版本 |
| 人物与关系 | 角色的欲望、需求、恐惧、障碍、秘密、选择与弧光 | Character / Relationship / Arc |
| 戏剧发动机 | 故事靠什么持续产生新的冲突和选择，而不是反复叙述设定 | Central Conflict / Stakes / Escalation |
| 因果推进 | 前一场如何迫使下一场发生？关键转折是否有铺垫和代价？ | Plot Causality / Turning Points |
| 观众信息 | 观众知道什么、角色知道什么，悬念、意外与情绪如何形成 | Reveal Plan / Audience Knowledge |
| 场景与 Beat | 每场戏谁想改变什么，采取什么行动，遭遇什么抵抗，状态如何变化 | Scene / Beat / Scene Objective |
| 对白与潜台词 | 不同人物声音是否真实；行动与停顿能否表达未说出口的意义 | Screenplay Dialogue / Action |
| 节奏与结构 | 哪些信息冗余、动作拖延、情绪没有建立；单集钩子和集末悬念是否必要 | Structure / Pace / Episode Arc |
| 类型与形式 | 短剧、微电影、连续剧和实验影片的表达约束是否符合内容 | Format Constraints |

这些要素可因题材而轻重不同。例如无对白短片仍需要戏剧动作与情绪转变；悬疑作品更重信息控制；情景喜剧更重角色关系驱动的戏剧机制。**不把某一种经典三幕结构当作全题材强制模板。**

## 三、建议提供三种创作路径

**共同创作**（适合用户有故事方向）：用户给核心设想，LLM 不断提出关键戏剧问题、备选情节、试写与改写；用户可在剧本层级直接修订，不被迫从零开始。

**AI 主导初稿**（适合快速探索）：用户提供目标、题材和制作边界，LLM 先形成可比较的故事提案，再发展为有因果、人物变化、Scene/Beat 和对白的草案；用户不是只能接受单一第一稿。

**现有作品改编/优化**：从用户提供的梗概、小说、剧本、Episode、Scene 或 Beat 进入；首先保留原文及使用条件，区分“理解原作”与“提出新的改写”，不默默改变人物事实或主题。

三种路径共用同一 Project 事实、版本、候选和下游影响机制；允许中途切换。

## 四、剧本创作的可迭代过程

以下是**系统可提供的能力集合**，不是必须逐个过审的固定门：

1. **形成戏剧核心**：主题、人物目标、主要阻力、结局变化、观众期待；LLM 主动识别空泛设定。
2. **探索不同剧情方案**：针对冲突、人物抉择和转折产生少量具有实际差异的候选，比较戏剧利弊、所需镜头/资产成本。
3. **建立跨场因果**：将关键行动、意外、人物选择、知识变化组织成可理解的情节推进，而不是只有事件排序。
4. **细化 Scene/Beat**：每场有功能，Beat 标出行动与反应、信息变化或情绪转移；允许多场构成同一大段落。
5. **写成可表演的剧本**：场景、动作、台词、停顿、非语言行动和声音信息要能支持专业导演设计，但不在剧本中僵化规定所有镜头。
6. **以不同专业视角复核**：剧作反驳、人物动机追问、对白朗读感、节奏删减、世界逻辑与连续性；反馈需要具体证据。
7. **差异化改稿**：支持微调某句、重写某场、改动人物弧光或重新构建全片；对不同变更提供范围和影响提示。
8. **正式采用与下游联动**：将采纳的剧本版本关联 Scene/Beat，并通知受影响资产、导演、Shot/Clip 与实际成片。

这里应确保“好故事”不是一键生成后直接进入 Shot。可以快速进入拍摄，但始终允许返回内容层改进。

## 五、Scene 和 Beat 的专业使用

**Scene 是戏剧单元，不等同物理视频片段**。同场戏可有多个 Beat；一场戏未必只有一处摄影机机位；一个导演 Shot 可能服务多个 Beat。

建议 Beat 表达（仅示意字段）：

- 谁正在采取什么行动？希望改变什么？
- 对方/环境如何阻止或反击？
- 观众掌握了什么新信息？是否产生新的期待？
- 这一拍开始和结束时，人物关系/情绪/戏剧情境发生了什么变化？
- 它为什么需要存在？删除后剧情是否损失？
- 与上下文承诺、悬念和人物弧光的关系。

Beat **不能简化成“每句对白一条 Beat”**；分解粒度应适合叙事与导演工作，避免无意义的对象膨胀。

## 六、LLM 的剧本质量诊断如何避免空话

不应只返回“人物塑造 8/10、冲突 9/10”。

专业诊断应尽可能包含：

1. **具体定位**：在什么 Scene、Beat、对白或动作处出现问题。
2. **剧作判断**：例如角色选择缺乏动机、反转未铺垫、冲突原地打转、观众比角色知道太多。
3. **依据与不确定性**：引用当前剧本具体事件；如果属于审美偏好，说清这是创作选择而非绝对错误。
4. **至少一个可操作改法**：写出新的动作/冲突/铺垫，说明不同改法的戏剧影响。
5. **与制作的关系**：修改是否要求新人物、资产、Scene、导演与 Shot；但不为了“更易生成”牺牲故事。

剧本质量检验应由人类创作者判断主导、专业 AI 提供依据；将来也可进行真实观众反馈，但不在 V1 强行引入一个虚构“必火预测器”。

## 七、短剧与多集故事设计（第一版保持简洁）

- 独立短片：侧重有限时长内的角色选择和情绪/关系变化；允许开放式或留白结尾。
- 单集短剧：侧重开场吸引、冲突推进、集内变化和必要的集末推动力。
- 系列作品：将长线角色关系和世界事实保存在 Project/Series 级，将本集事件与 Beat 放在 Film/Episode 级；跨集事实引用版本而不复制多个矛盾设定。
- 不在 V1 绑定具体短剧爽点模板、特殊 POV、导演大师人格化包，这些以后在明确价值验证后扩展。

## 八、内容变更的真实工程后果

假设第 6 区审片发现“父亲递钥匙后女儿立刻和解”不可信，第 1 区提出加入一次“犹豫却没接钥匙”的行动和新台词。正式采纳后：

- 新版剧本仍属于同一影片/Scene 及关联 Beat 的可识别修订。
- 第 3 区接到导演层复核需求：原 22 秒 Shot 的情绪节奏是否仍成立？
- 第 4 区评估动作/台词/时长是否需要改变，以及现有 Clip 映射是否仍合适。
- 第 5 区已生成的 Run/Take 不被覆盖；标记与新方案的符合程度待审片判断。
- 第 6 区历史剪辑版本仍可回看；只有真正受影响的素材选择和时间线需要调整。

## 九、V1 可检验的能力

| 场景 | 必须能判断什么 |
|---|---|
| 一句话创意 | 可提出真正不同的故事冲突，而不是几个只换措辞的摘要 |
| 人物行为不可信 | 能指出动机断层及补救动作，指出它会影响哪些后续 Beat |
| 剧情推进缓慢 | 能定位重复 Scene、缺少状态变化和冗余对白 |
| 全剧对白风格雷同 | 能说明人物表达差异，给出符合人物性格的改写 |
| 用户局部重写 | 不丢失其他已确认的剧本和导演事实，保留版本 |
| 用户已提供剧本 | 不强制重走创意发散和大纲阶段 |
| 下游质检回流 | 能把具体 Take 的内容问题定位回 Scene/Beat，并产生可选择的改稿 |

## 十、下一轮审阅需要决定

1. 默认启动时用户更希望**共同创作**还是**AI 主导初稿**？可先建议共同创作，但不预设必须人工写所有内容。
2. 第 1 区如何展示全片结构、Scene/Beat、正文剧本和专业诊断，避免像普通聊天工具？
3. 不同剧本修订是否全部保留为候选，还是提供明确的工作草稿与里程碑版本？
4. 对多集是否 V1 就做基础 Series 事实层，还是先把共享资产与多集预留为轻量能力？

本文件不要求“一切剧本达到某个神秘分数后才能拍”，也不允许 AI 把低质量但格式完整的剧本称为已经完成专业创作。
