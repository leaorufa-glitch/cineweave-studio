# V1.3-01｜专业 LLM 全流程创作协作机制

> **状态：草案，待审定**；日期：2026-10-10  
> 基于 V1.1 已确认的三层架构和 V1.2 仍在审阅的业务设计。本文是**产品与智能协作机制设计**，不是要求建立固定数量 Agent 或按单一死板流程执行。

## 1. 产品定位：持续专业创作，而非串联六个聊天机器人

创作者始终围绕**同一个影视工程**工作。六大工作区提供不同专业视角；专业 LLM 在每一区参与真实的构思、判断、写作、修改、比较和复核。LLM 的价值不是给每一步附上一段“AI 说明”，而是帮助作品持续变好。

要避免两种失败：
- **只是流程完整、内容平庸**：大纲、资产、Shot、Clip 的字段都齐了，但人物、戏剧、表演与最终视频没有感染力。
- **只是 AI 显得聪明、工程无法管理**：通用 Agent 自行决定步骤与状态，在长会话、跨区修改、模型异步任务和版本变化中丢失事实。

因此建议采用**专业创作任务 + 统一事实上下文 + 候选方案/专业证据 + 系统正式采纳 + 后续影响传播**的共同机制。

## 2. 贯穿六区的专业工作能力

| 区域 | LLM 要做的专业创作工作 | 典型高价值问题 |
|---|---|---|
| 1 前期创作 | 故事开发、剧作诊断、人物弧光、对白与情节迭代 | “这次选择为什么迫使角色改变？第二场戏有没有真正推动冲突？” |
| 2 资产设计 | 美术方向、人物状态/可辨识性、场景与声音风格创作 | “角色新造型是否暗示错误身份？参考图是否能支撑目标镜头？” |
| 3 导演创作 | 场景解释、人物动机、表演调度、摄影/声音表达与 Shot 决策 | “为何用连续双人镜头而不是反打？这个停顿创造了什么情绪？” |
| 4 分镜与生成规划 | 保持导演意图、设计视听时序、构图、镜头运动、参考及 Clip | “能否在 12 秒内完成这两个镜头且保留对白和动作因果？” |
| 5 生成制作 | 面向模型模式的语义编译与真实 Take 问题归因 | “人物变脸源于引用失效、描述冲突还是生成随机性？” |
| 6 审片与成片 | 以真实画面和声音评估叙事、表演、连续性、节奏和情感 | “转折观众能否理解？问题在剧本、导演、剪辑还是视频生成？” |

各专业职责能随作品变化；不预设每个专业必须是独立账号、长期驻留进程或某个特定大模型。

## 3. AI 的四种实际工作形式（建议）

**A. 联合创作**：与用户进行针对性的创作讨论，提出选项、冲突、修改与判断。允许开放式对话，但对正式事实的修改必须落到可审阅产物。

**B. 专业提案**：主动或应请求产出一个可对比的版本，如“更克制的表演方案”“更有悬念的第二幕”“两种不同的镜头叙事结构”，说明戏剧/视听依据和风险。

**C. 专业诊断**：对剧本文本、参考资产、分镜计划、真实音视频分别查找问题，给出具体证据、影响对象、是否确定与建议返工方向。发现“不知道”“无法观看真实视频”时要如实标注，不能猜测已经验证。

**D. 有限自动推进**：在用户授权范围内进行一些低风险例行任务、补全草案和检查；但不能自行覆盖关键剧作决定、导演决定或花费超预算进行实际生成。

这四种形式可在每个工作区出现，不能将“聊天窗口数量”当作 AI 能力架构。

## 4. 系统构造准确的任务上下文

在每次专业任务开始时，**系统负责构造上下文，LLM 不靠聊天历史猜项目事实**：

- 定位：Project/Film/Scene/Beat/Shot/Clip/Take、相关版本与任务 ID。
- 创作目标：这场戏在全片中的功能、人物欲望/阻力/变化、导演意图与不可改动项。
- 已确定事实：剧本和人物当前正式版本、资产文件、导演与分镜决定、时间约束。
- 相关前后情节：人物秘密、观众目前知道什么、上一场到下一场的信息衔接。
- 工作历史：候选方案、采纳/拒绝理由、已发现错误、来自审片的真实证据。
- 真实媒体：能够访问和分析的图片/视频/声音及出处；不可访问时明确缺失。
- 任务约束：输出目标、允许修改范围、模型能力、预算和用户授权。

通过“当前任务所需资料 + 足够前后文 + 已批准艺术决定”控制上下文，而不是每次把全项目文本不加选择地塞入模型。

## 5. 创作结果和正式数据分开

建议在业务层区分以下成果：

| 成果 | 作用 | 是否直接改变当前影片？ |
|---|---|---|
| **Idea / Candidate** | 候选构思、台词、导演方法、镜头计划 | 否 |
| **Proposed Revision** | 对明确正式对象提出可比较的增删改 | 否 |
| **Professional Finding** | 指出问题、证据、可能原因与影响范围 | 否 |
| **Adoption Decision** | 用户或预先授权规则正式采纳候选 | 是：生成新正式版本 |
| **Committed Revision** | 被系统记录且可溯源的新事实或创作决定 | 是，但不修改历史输入快照 |

重要：**AI 分析和建议可以很大胆；正式状态变更必须可追溯。** 不应让 AI 直接在隐藏后台静默重写已确认的剧本、Shot 或父 Take。

## 6. 创作质量：既敢创作，也敢批评

为了避免机械剧本和空泛导演话术，LLM 的专业任务不应只要求“按模板填写字段”。应允许在任务中：

- 提出不同而合理的表达路径，并比较各自的戏剧代价。
- 主动指出剧情的因果缺口、人物动机不足、节奏疲软、镜头选择缺乏目的等问题。
- 对观众信息状态进行判断，避免创作者全知视角导致故事悬念失效。
- 说明哪些判断来自真实剧本/影片证据，哪些属于审美建议或尚待实测的风险。
- 让用户选择深度：直接创作、与 AI 共创、仅审查与微调；其差异在**操作主导权**，不是“AI 是否参与”。

**不推荐**把艺术质量简单压缩成一个 0–100 的神奇分数；若采用指标，只能是辅助结构和问题定位，不能代替真实创作决策与观众感受。

## 7. “专业 AI 协作”不等于必须有六个 Agent

V1 必需的是可调用的专业能力和明确的输入输出责任，而不是固定人数。工程可选择：

- 单一高能力模型按任务装载专业合同；
- 不同专业任务采用不同模型或配置；
- 对重大的剧作/导演问题使用交叉复核；
- 在明显有增益时采用多轮候选、争议与修正。

何时并行、何时复核、何时切换模型由后续 V1.5 的能力、费用、延迟与质量验证决定，不在当前 V1.3 文档直接规定多 Agent 架构。

## 8. 跨区的创作变更实例

**审片发现“女儿的原谅太突然”**：第 6 区 LLM 根据实际 Take 与剧本，提出明确证据和问题来源；第 1 区 LLM 设计两种情节铺垫并检查人物动机；用户采纳后创建新的剧本版本；系统标出可能受影响的 Scene/Shot/Clip；第 3/4 区重新评估导演方案及镜头计划。旧视频与旧剧本保留，允许比较。

**第 4 区发现 Director Shot 不适合某模型**：专业 LLM 可以提出分段原生续接、重做分镜参考或调整动作设计，但不能因为“更容易生成”就擅自把导演的一镜到底改成两次切镜。

## 9. 后续工程应验证的行为

1. 任意区的专业任务能拿到正确版本的剧本、人物、资产及导演/分镜决定。
2. 未采纳的 AI 候选不会污染正式影片。
3. 重要正式版本变更后，关联下游能够识别待复核，而不是假装仍符合最新方案。
4. LLM 可以给出跨区诊断及证据，但不能绕过系统直接花费费用、改选父 Take 或覆盖视频文件。
5. 从 Scene、Asset、Director Shot、Clip 或已有 Take 进入，AI 能恢复其必要上下文而无需让用户重走所有创作步骤。
6. 演示任务不仅“字段齐全”，剧本、导演和审片输出必须由专业审查评价其表达质量。

## 待审定的产品细节

- 自动推进和人工决策的默认配置及快速切换方式。
- 专业 AI 的显式意见冲突怎样呈现，避免用户被大量低价值提案淹没。
- 候选方案是否默认保留，以及多久归档。
- LLM 无法访问某媒体时，业务层如何降级与提示。
- 跨区反馈是否由用户发起为主，还是允许事先授权的主动诊断提醒。
