## 一、核心产品形态：智能生产调度台，不是一个“万能提示词按钮”

第 5 区的用户真正需要完成的目标：从第 4 区已经批准的**视听执行计划**，可靠地生成真实视频/声音，控制花费、模型模式和上下文依赖，获取若干实际可播放 Take，审看质量并选择继续生产或返工。

第 5 区建议由五类直接可操作的能力构成：

| 用户工作 | 必须看得见什么 | 必须可以做什么 |
|---|---|---|
| **待执行 Clip/批次** | Film / Scene / Shot / Generation Clip 的真实来源、15 秒以内时长、当前正式版本 | 按场景/批次选择合法任务并决定是否执行 |
| **编译预检** | H3 路由/模式、实际图板媒体、声音样音、素材上传状态、参考数量、模式不兼容项 | 切换**已验证**合法模式、查看 Prompt 和差异、修改计划或回导演/分镜 |
| **费用与授权** | 本批次与续接依赖的预计费用、已使用额、价格未知/动态风险 | 授权一次或有界预算内批量任务；超预算需再次授权 |
| **异步生产与依赖** | Run 队列、上传状态、远端任务 ID、结果状态、等待父 Take/Context 原因 | 暂停未提交的任务、合法取消（仅支持的路由）、恢复、处理未知提交 |
| **真实结果与返工** | MP4 可播放、带真实声音、Take 版本/来源、技术检查、质量状态 | 试听/试看、选择 Take、做专业评注、重新生成或反馈上游 |

无效模式、缺失媒体、未知费用或 Motion Context 不存在时，生成按钮不可伪装成可执行。重要艺术冲突不能由模型编译器静默解决。

## 二、业务输入与三段编译——专业自由、机器严格

### 2.1 创作源（不得静默改写）

- Script / Scene / Beat 正式版本；
- Director Shot ID/版本、不可改变的摄影/表演/叙事要求；
- 第 4 区 Shot Execution Design + Generation Clip ID/版本、Shot-Clip 时间映射；
- 对白**逐字原文**、说话者、**基准语速与导演表演语速、独立停顿**、音效事件/音乐意图；
- 人物 Look **整张 2×2**、场景**完整 1+3**、关键道具**完整 1+3**及其**采用媒体版本**；
- Shot 级分镜/关键帧（**不同于**正式人物/场景/道具图板）及目标首/尾连续性；
- 计划的独立、参考引导、原生续接策略与审片目标。

### 2.2 标准执行计划（模型无关）

将上面的事实表达成结构化、可编辑、可审查、**不含供应商字段**的 Audiovisual Execution Plan；AI 可建议改进对白密度、Shot 边界和动作因果，但不能未经导演决定把 22 秒长镜头变成两个有切镜的 Shot。

### 2.3 模型/模式选择（明确“不能一起要求”的约束）

**方案 R：多模态参考驱动**  
用于强调同一角色 Look、场景图板、道具图板与声音参考的一致性。按当前路由已文档化的参考槽位编译，整张图板当作**一个真实媒体引用**，每格是内部内容，不拆四张正式媒体。

**方案 F：首帧/首尾帧驱动**  
用于强调某个实际 Shot 的开始/结束画面与构图。首帧必须是单幅**导演/分镜级的电影画面**，而不是人物或场景四视角图板。**公开自部署 H3 模式下 F 与 R 互斥**：不可同时提交 `first_frame` 与 `reference_image`。要由用户/专业导演明确权衡可行模式，不能悄悄丢掉必要的人物身份约束。

**方案 C：真正原生 Motion Context 续接**  
只在特定可调用接口已验证存在、已保存父 Take 的 Motion Context，并且父结果/权限/路由均满足时才标记为“真正续接可执行”。**目前公开 Darl MiniMax-H3 与 RunningHub 文档未给本项目可直接执行的原生续接合同**；用户报告的自部署实现先登记为「待核实自有续接 Adapter」。

**方案 S：同一次视频的二次采样/再生成**  
Darl 自部署网关文档披露了 `second-sampling`；它是已有 Run 结果的质量/采样分支，**不是新时间段的 Generation Clip，也不是 Motion Context 续接**。RunningHub 文档未提供独立二采端点，其 `upscale` 是创建工作流时的参数，不自动代表同一机制。

### 2.4 编译器建议边界

编译过程应为：**模型无关执行计划 → 选择经过资料核验的路由/模式 → 模式专属 Typed Compiler → 上传/引用准备 → 合法性/权限/预算检查 → 不可变 Compiled Input → Run**。

专业 LLM 可以建议 Prompt 的多镜头、对白、构图、声音描述；**字段名、类型、取值、参考数量、素材传输和响应解析由可测试的确定性适配器负责**。禁止使用“模型名字符串包含 H3 就统一编译”的做法。

建议先确定**主生产逻辑 Adapter**，可选渠道无需一开始全部实现（不意味着 V1 必须微服务化）：

- `OwnedH3`（首要）：用户自有 H3 模型和原生续接服务；**服务器当前未开机**，设计优先保留真实参考、多镜头、声音、父 Take/Context 依赖，使用 Mock 先测。实际请求和 Media/Context 字段必须等自有服务器协议可读后确认；**不得照搬 Darl API**。
- `DarlSelfHostedH3`（文档对照，按需）：Darl 公开代理声明 `MiniMax-H3` + `content[]`，但**不是自有 H3 已支持该协议的证据**。
- `DarlRunningHubH3`（可选临时测试）：`runninghub-minimax-h3` + 专用上传 ID；用户确认仅供测试，**不是正式生产必实现 Adapter**；无已文档化的取消/独立二采/续接。

其他视频模型（如 Seedance/Wan3）之后也各自提供 Typed Compiler，并据真实能力声明模式；不能因为用户能调用中转站就默认特性相同。

## 三、参考资产与图片/声音的实际处理方式

### 3.1 完整图板是第 2 区正式资产

- `Character Look` → 一张人物 2×2 整板 MediaFile。
- `Location/Environment` → 一张场景上 1 下 3 整板 MediaFile。
- `Hero Prop/State` → 一张关键道具上 1 下 3 整板 MediaFile。
- Voice Identity → 基准语速与当前正式样音（若真正存在），第 3/4 区添加某场某句表演语速覆盖。

**不可**在第 5 区因为模式限制把四视角拆成四个新正式 Asset，也不能把“上 1 下 3 图板的四格”直接解释为“影片镜头顺序”。如果模型不能可靠理解完整图板，生成预检明确不兼容或风险，提供需要用户/导演参与的**受支持方案**，而不是编造未批准的图片重组行为。

### 3.2 选择有效参考，不自动把资产全部塞进模型

第 4 区可以关联许多美术/声音资产，但单个 H3 模式的媒体数量有限。编译器要按当前 Shot 的主体、剧情关键物件和空间重要性确定**候选绑定的优先级**，并清楚显示**“计划引用”“实际将提交”“未提交及原因”**。改变必要身份引用的优先级需要可审阅决策，绝不静默丢弃第 3 区不可变导演意图。

### 3.3 不同上传契约

- `gpt-image-2`：公开文档的图片生成返回 **`data[].b64_json`**，必须解码、检测、存入持久媒体存储并记录来源/原始质量；不能当作长期可用外链。图板内容 QA 单独完成。
- 自部署统一 H3：`content[].image_url.url` 等接受公网 HTTP(S) 或 Data URI；标准文件网关上传并查询 URL 只是让本地/私有媒体成为合法视频输入的方式之一。要校验 URL 的有效期、可被上游服务访问以及隐私授权。
- RunningHub H3：先通过 `/runninghub/v1/uploads` 上传，保留**渠道/密钥归属的网关素材 ID**，再引用上传 ID。旧渠道/密钥下的 ID 不可假定跨渠道有效。
- 同一 `MediaFile` 可以映射到**不同路由上传记录**，但上传记录与文件身份不同；不要重复上传已经合法缓存且确认有效的媒体。

### 3.4 模型参考与声音身份不能混淆

Voice Identity 及样音可复用是**创作/资产事实**；当前 H3 模式是否能输入声音样音、是否尊重角色语速、是否能稳定跨 Clip 保持音色，必须分别判断。没有支持精确 `speed` 字段时可以编排自然语言的表演指令，但**不能创造参数或声称锁定声纹**。第 6 区必须真正听音频。

## 四、Clip、Run、Take：每次生成都能追溯

| 对象 | 真正代表什么 | 不变量 |
|---|---|---|
| **Generation Clip Plan** | 一段不超过 15 秒的视听生产目标 | 关联一个或多个 Director Shot，可修订；不等于电影的切镜 |
| **Compiled Input Revision** | 某具体模式的完整合法参数、真实引用与生成策略版本 | 不可变；生成时冻结，未来资产换版不回写 |
| **Run** | 一次有预算与提交记录的真实模型尝试 | 包含路由、远端任务 ID、提交/完成时间、错误、实际费用、父依赖（若有） |
| **Take** | 真正成功取得的影音媒体候选 | 关联生成 Run、持久 MediaFile、真实技术属性与专业审片状态 |
| **Native Motion Context** | 父 Run/Take 实际可用于“下一时间段”的真实时序/运动上下文 | 必须有来源、类型、可访问性、使用资格与版本证据 |
| **Continuation Link** | 子 Run 消耗的是哪个实际父 Take/Context | 改选父 Take 后不得暗中继续使用旧父上下文 |
| **Second Sampling Link** | 同一次视频的新采样结果依赖哪个源 Run/latent | **不是续接关系**，不能放到新的时间段 |

一个成功 Run 不等于 Take 一定可播放；有 Take 不等于符合导演表达；已选 Take 不等于已经加入成片 Timeline。

## 五、可靠异步调度：生产 DAG，不按剧情线性等待

### 5.1 子任务类型

- **资产上传准备任务**：检查持久媒体并进行当前路由必需的上传/URL 有效性确认；
- **普通生成 Run**：独立任务，可受预算/并发约束并行；
- **真续接 Run**：有真实父 Take + Motion Context 依赖，父结果获得适当 QA/授权后执行；
- **同 Run 二次采样/放大**：仅受支持路由，依赖原成功 Run 和仍可用的内部生成数据；
- **媒体下载和验证**：生成成功后拉取真实视频并持久化；防止有 URL 却从未下载；
- **专业 QA/审片任务**：可辅助 AI 观察，但必须基于真正音视频，人工可纠错；
- **成片 Render**：第 6 区对已选真实 Take 的非破坏时间线执行，独立于 H3 单段生成。

### 5.2 必须正确区分“远端状态”和“本地状态”

| UI/业务状态 | 含义 | 典型来源 |
|---|---|---|
| `needs_inputs` | 缺图板/Voice 或当前真实媒体失效 | 本地校验 |
| `needs_route_validation` | 当前模式/参考输入是否合法未确认 | 能力矩阵 |
| `waiting_authorization` | 费用/调用权限不足或未知 | 预算与授权 |
| `waiting_parent_take` | 需要真实可采纳父 Take，而非 Clip 名称 | 续接 DAG |
| `waiting_motion_context` | 父媒体有了，但仍无可用/可追踪 Context | 续接接口 |
| `ready` | 预检通过，可以按预算提交 | 本地 |
| `submitting` / `submission_unknown` | 提交中或网络异常，无法确认是否已接受 | 本地记录与远端查询 |
| `queued` / `running` | 远端受理/执行中 | 路由独立状态映射 |
| `remote_succeeded` | 远端声明成功，但媒体可能尚未持久化 | provider 状态 |
| `media_ready` | 已下载、可解码/可播放、校验时长/音轨/尺寸 | 媒体检查 |
| `take_pending_review` / `take_accepted` / `take_rejected` | 真实影音专业审片与采用状态 | 第 6 区 |
| `failed` / `cancelled` | 根据原始服务状态和用户取消动作分别归因 | 不能只按网关 `failed` 判断 |

不能把上述列表直接当成唯一数据库 Enum；未来实现可拆 `submissionStatus`、`remoteStatus`、`mediaStatus`、`reviewStatus` 组合以避免状态爆炸。

### 5.3 自部署与 RunningHub 的状态映射差异

**自部署 MiniMax-H3**：文档返回 `queued`、`processing`、`succeeded`、`failed`，成功 URL 位于 `content.video_url`。文档说明取消后本地查询可能显示 `failed`，因此必须记录“取消操作及上游响应”，将失败原因与主动取消区分。

**RunningHub H3**：文档返回 `queued`、`in_progress`、`completed`、`failed`，成功 URL 位于 `video_url`。上传操作返回素材 ID，**素材 ID ≠ 视频任务 ID**。RunningHub 网关当前没有已文档化的任务取消接口。

提交后若发生网络超时且可能已经付费排队，必须记录 `submission_unknown`、输入摘要和当次时间，不应**未经核实立即重复扣费提交**。是否支持幂等键或检索先前未知任务，要按路由真实核对；没有可靠检索方式就提示风险与可操作复核路径。

### 5.4 真实续接 DAG

一个 22 秒连续 Director Shot 可以由 **B1 12 秒 + B2 10 秒** 两个 Generation Clip 生产，仍旧是**一个 Shot**。B2 只有在**当前选中的合格 B1 Take、真实父 Run、可用对应 Motion Context**都存在且目标路由/模式证据满足时，才能作为原生续接提交。

更换 B1-TakeA 为 B1-TakeB 时，原 B2 子链保留为旧父历史；当前电影版本如果需要 B2 应基于 TakeB 重新判断/生成，不能偷偷把已生成的旧 B2 宣称来自新父。其他独立 Clip 不被阻塞。

**不支持原生续接时**：允许根据专业判断提议“有意义的电影切镜+独立生成”“首尾关键帧引导”等替代，但这会改变导演连续镜头的叙事和摄影选择，必须回到第 3 区由导演决定，不能静默降级后仍标记为续接。

### 5.5 费用与任务预算

任务提交前记录：当前模型/路由/模式、将提交 Clip 数量、预计每段时长、参考媒体（可能额外计费）、上限/自动重试额度、是否包含二采或潜在续接子段、实际价目来源与更新时间。

RunningHub 公开文档当前以约 $0.06/秒 × 账号分组倍率为示例；**价格有变化可能，且自部署与 RunningHub 计费不必相同**。供应商账单/网关 usage 为实际依据；如果获取不到可靠估价，显示**未知**，不虚报固定金额。

支持用户对明确范围、上限和重试次数**提前授权**，在范围内自动完成；超范围必须暂停并再次取得授权。设计/模拟/查资料不发起任何付费请求。

## 六、模型输入编译的专项预检规则

| ID | 条件 | 应如何处理 |
|---|---|---|
| PRE-01 | Clip 时长 >15s | 拒绝生成；回第 4 区合理拆计划，不强制新增导演切镜 |
| PRE-02 | 自部署 `reference_image` + `first_frame` 同时存在 | 拒绝无效模式，展示参考驱动/首帧驱动的互斥与可选方案 |
| PRE-03 | RunningHub 提交未上传到**该渠道**的素材 ID | 先合法上传/校验渠道归属，不能把平台 `file_*` ID 填进去 |
| PRE-04 | 图片模型返回 `b64_json` 但未入库 | 不能选择为正式图板/提交 H3；先保存真实媒体 |
| PRE-05 | 正式图板存在，但复合布局在目标视频模式未实测 | 如实显示“参考形式效果待验证”，不伪造已锁定人物/空间；按用户质量要求决定是否可继续 |
| PRE-06 | 声音样音实际存在但目标模式不支持 | 不能谎报声纹锁定，可用合法的声音描述并提示风险，或按创作要求阻断 |
| PRE-07 | 计划真续接，但没有 Context 或只提供末帧 | 保持 `waiting_motion_context` / 不可续接，不标成原生续接 |
| PRE-08 | 自部署 `second-sampling` 请求试图改变 Clip 时长/接续动作 | 阻止错误用法；二采对应同一时间段的新采样 |
| PRE-09 | 模型路由不支持取消却显示“已取消成功” | 不允许；必须按真实路由显示“未提供远端取消能力” |
| PRE-10 | 已提交请求响应丢失 | 进入未知状态/核对；不得无条件重复付费 |
| PRE-11 | 参考图片超出路由数量或占据冲突角色 | 显示每张实际用途和模式冲突，提出可审阅的资产/模式调整方案 |
| PRE-12 | 正式编译请求覆盖历史资产版本 | 不允许修改旧 Compiled Input/Run；创建新修订并提示相关计划待复核 |

特别需要实测：一个人物整宫格、一个场景 1+3、一个道具 1+3 在 H3 Ref 模式下是否被理解为**同一对象的多视图**，而不是画面分屏或多个复制人物。单有“reference_image 槽位合法”并不证明电影画面可控。

## 七、从第 5 区到第 6 区的真实交接

一个 `remote_succeeded` Run 需要继续完成：

1. **下载/入库真实媒体**：保存长期可访问视频（不是只存临时 URL），记录来源、hash、字节数、实际长度/画幅/帧率/音轨；失败的下载可独立重试，避免重新生成付费视频。
2. **技术检查**：可解码/可播放、时长、音轨、声道、静音或异常、输出文件状态；模型声称原生音画并不自动证明当前媒体真的有合适对白。
3. **准备真实 Take**：绑定 Clip、Run、Compiled Input 和最终 Video MediaFile，不覆盖同 Clip 的其他候选。
4. **创作质量审查**：镜头/表演/对白原文/语速/连续性/角色/场景/道具/声音的实际符合度，必须有真实媒体证据。
5. **采纳/退回**：用户可比较多个 Take，在第 6 区选用，并产生下游续接/成片影响。

第 6 区详见 [V1.3-14 审片和成片合同](14-REVIEW-TIMELINE-FINISHING-V1.md)。

## 八、验收清单（未来代码测试用，不代表已执行）

| 用例 | 预期 |
|---|---|
| **GEN-01** 自有 H3 Mock 与可选代理路由（如果启用） | 自有协议未取得时只运行 Mock，不猜请求字段；如启用外部代理则分开编译、解析，不互相污染 |
| **GEN-02** 图板媒体来自 GPT Image 2 | 保存真实 Base64 解码媒体及版本，能够导入两类 H3 的合法引用路径 |
| **GEN-03** 多资产参考绑定 | 保留人物/场景/道具整张图板的顺序、用途与来源；不产生四张正式拆格 |
| **GEN-04** 首帧和参考混合 | 公开自部署路由被正确拒绝编译，解释互斥并给出导演可用选项 |
| **GEN-05** RunningHub 临时通道被选用但素材上传失败 | 不能使用缺失/跨渠道 ID 提交收费视频；该可选通道未实现不阻挡主线 |
| **GEN-06** 两个独立 Clip 与一个等待父 Context 的子 Clip | 独立任务可按预算并行，子任务明确等待实际父 Take/Context |
| **GEN-07** B1 换用另一 Take | B2 旧父链不删除，当前续接资格重新评估 |
| **GEN-08** 自部署二次采样 | 同源 Run 创建新采样分支，不生成“下一段剧情”的假续接 |
| **GEN-09** Run 成功/音视频损坏 | 远端成功≠真实媒体已就绪；支持针对媒体重下载而不是重付费生成 |
| **GEN-10** 用户主动取消自部署 Run | 即使统一网关最终查询是 `failed`，仍保留取消意图/上游响应与退款核对 |
| **GEN-11** 远端提交超时 | `submission_unknown` 保留不可变请求摘要，不立刻重新提交 |
| **GEN-12** 声音样音/语速当前模式不兼容 | 提示风险、合法编译或阻断，不发不存在的 `speed`/voice API 字段 |
| **GEN-13** 浏览器刷新或 Worker 重启 | 已提交 Run、远端 ID、真实文件和预算账目可恢复；没有幽灵任务 |
| **GEN-14** Take 创作很差但远端成功 | 用户可拒用并反馈第 2/3/4/5 区，绝不自动判成片通过 |

**本阶段开放的关键接口阻断项**：真实 Motion Context 续接适配器缺合同；没有实际项目账号/密钥验证网关通道可用性、输出质量和当前结算；V1.5 应将其列为优先级最高的实测任务之一。

## 九、最短推荐实施切片（非代码任务）

- **S1：真实媒资 + 一条非付费 Mock Run**——项目/Clip/编译快照/媒体/状态能贯通。
- **S2：优先构建用户自有 H3 的 Typed Adapter 边界、上传/轮询/下载与原生续接 Mock**——自有服务器开机/实际协议可用后再联调；RunningHub 仅在临时测试有必要时独立补充。
- **S3：多图板 + 声音参考 + 实际 Take QA**——从第 2 区到第 6 区的跨区可靠引用。
- **S4：DAG、选 Take、真续接、二采与父分支**——真续接只能在用户提供协议并实测通过后标可执行。
- **S5：成片输出与回写问题**——非破坏性时间线、声音、导出、稳定历史。

不引入复杂微服务或永久运行的六套 Agent 作为前置条件。先让**一个 80 秒短片**可全流程真实使用并验收，再扩展并发和其他模型路由。
