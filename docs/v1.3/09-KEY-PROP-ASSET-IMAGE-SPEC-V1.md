# V1.3-09｜第 2 区关键道具资产与图片生成规范 V1

> **状态：产品形式已确认（PD-009），详细技术/QA 内容仍为草案；2026-10-10。**  
> 用户已明确确认：**关键道具一张完整 1+3 图板，普通环境道具归入场景资产，不强制独立出图**。参见 [PD-009 正式决策](../decisions/2026-10-10-HERO-PROP-BOARD.md)。  
> 本文仅在已批准的图板结构之上补充状态、提示词、质量和模型适配建议。  
> 当前仅讨论文字设计；无实际图片/视频生成，无付费模型调用，无应用代码或关系图。

## 1. 核心建议：道具按重要性分级，不把所有物品资产化

专业影视道具的价值在于叙事信息、动作、人物关系和镜头连续性，不只是图片是否漂亮。

| 道具类型 | 剧情职责 | 推荐 V1 图片策略 |
|---|---|---|
| **叙事关键道具**（Hero Prop） | 核心冲突、交接、解谜、悬念、身份、重要特写等 | **推荐一张完整、可复用的 1+3 道具设计图板**，带简明外观事实，作为当前正式造型候选 |
| **反复出现的连续性关键道具** | 多个 Clip 中需要保持同一具体外观 | 视跨镜头重复频次、外观复杂度决定是否建立整合图板；重要者按 Hero Prop 处理 |
| **普通布景/环境陈设** | 营造生活感、空间年代与材质 | 通常作为场景空间事实和场景 1+3 宫格的一部分，不强制单独生图 |
| **一次性、不承载叙事的物件** | 简单临时道具或画面陪体 | 可以在导演/分镜/Clip 中描述，不强制建资产 |

**正式方向已经确认（PD-009）**：剧情关键道具默认使用一张完整 1+3 图板，普通陈设归场景；**具体像素、提示词、媒体验证和复杂道具状态细则仍是草案**。

## 2. 已确认的一张正式“主 1 + 辅 3”关键道具图板（视角细化供审定）

已确认采用**上方大主图 + 下方三张辅助视图**；但道具不是空间，不能机械复制“反打/行动区/侧向场景”的四项内容。

| 图板区域 | 主要职责 | 推荐展示内容 |
|---|---|---|
| **上方大主图：身份锚点** | 一眼确定“这件具体道具长什么样” | 整件物体完整可见、最有辨识度的主观察角度（通常为中性的 3/4 角），轮廓、材质、颜色、特征位置清晰 |
| **下方左：反面/第二结构视角** | 防止物品反转时换形 | 背面、底面、侧面或另一结构角度；与主图是同一件物品 |
| **下方中：剧情关键细节** | 锁定必须被观众认出的特征 | 钥匙齿形、戒指刻字区、独特损耗、印记、机械机关、纸面重要局部 |
| **下方右：尺度/功能/连接关系** | 约束人物持握与实际使用的可信程度 | 道具合理相对大小、开合机构/连接方式、厚度、与配套物的关系；**不默认放入角色手部**，避免视频模型误把参考手当作角色表演 |

### 2.1 重点在“信息职责固定”，不是每种道具视角固定

- **钥匙、戒指、手表等小型立体道具**：反面、结构细节、厚度或尺度很重要。
- **信封、书信、证件、照片等平面或文字道具**：主图可用正面正视，辅助图可以是反面、局部内容/材质、厚度或尺度；无须为了“3/4 角度”反而看不清内容。
- **箱子、机械装置、可开启道具**：结构反面、功能细节、开合方式比较重要。但**永久破损/剧情变体不能偷偷混入同一正式状态板**。
- **大件交通工具或复杂交互装置**：某些更接近场景美术与空间调度，允许在专业审阅中判断更适合场景/道具复合设计，而不是强行一套统一机位。

**大主图优先能辨认完整物件**。三个辅助格不能小到关键刻字、轮廓或尺度毫无辨识度。整体画幅、实际像素、上下高度比例和压缩要求都应等待图片模型实测决定；不能编造 gpt-image-2 当前聚合路由支持的格式。

**重要资产形式**：一个道具身份与一个正式外观/可见状态，默认选用**一张当前正式整合图板**作为一个 MediaFile；生成/导入的候选及被替换版本可以作为历史保留。不要默认将四格拆成四张正式资产。第 4 区另行创作的镜头特写/关键帧并不是第二个正式道具身份。

## 3. 道具身份、设计版本、剧情状态与使用动作必须分离

| 对象 | 解决的问题 | 父女车站的旧钥匙案例 |
|---|---|---|
| **Prop Identity** | 故事里是否为同一件实体 | 父亲留给女儿的同一把黄铜钥匙 |
| **Prop Design Revision** | 稳定的形状、材料、齿形、尺寸、磨损和标识 | 黄铜、旧钥匙头、特殊齿形、某处磨损 |
| **Prop Visual State** | 物件因剧情事件形成持续可辨外观变化 | 钥匙完好／之后折断；信封未拆／已经开封 |
| **Adopted Board Revision** | 当前正式采用的真实完整图板文件、版本、来源 | PROP_KEY_01 / intact / Board Rev3 |
| **Shot/Clip Action State** | 某时刻谁拿、哪只手拿、物件在哪里、何时移动 | 父亲右手递出，女儿右手接过，之后放入口袋 |
| **Observed Take State** | 实际视频真的呈现了什么 | 生成片段中钥匙突然变形或换手 |

**不能因换了持有人、左右手、拍摄机位或景别，就生成新道具身份**。如果影片中出现剧情上不同的第二把钥匙，即使样式很像，也需要单独 Prop Identity。若物体在事件后形成持久可见的破损/拆封状态，建议为该 Prop Visual State 补**另一张该状态的整合图板**，仍属于同一 Prop Identity，而非把完整和折断两种永久状态放进一张“同状态”正式图板。

**真正只是在使用中的开合演示**，可作为辅助图呈现机构功能；**叙事中已经不可逆拆封/损坏的前后区别**应当按状态记录，避免后续 Clip 把两种状态混用。

## 4. 道具生成和采纳流程（推荐）

1. 从已采用剧本、重要动作和导演意图识别需要真正保持一致的**同一件物品**；普通陈设优先借场景图板。
2. 专业美术 AI 提议该道具的身份特征（形状、材质、尺度、颜色、故事意义、固定细节），用户可导入真实已有参考。
3. 由道具类型选择最合适的**大主图 + 三项辅助内容**；生成或导入**一张完整图板候选**，而不是产出四张互不相关的参考图。
4. 用户与美术 AI 对照各格，检查是不是**同一实体、同一外观状态**；必要时重修整张候选，合格后采纳当前正式版本并保留历史来源。
5. 将 Prop Identity、视觉状态、整张正式图板版本及职责提供给第 3/4 区；在 Shot/Clip 中另外描述手势、表演、空间位置、动作时序和即时状态。
6. 第 5 区以当前真实模型/模式适配合法图片输入；第 6 区检查实际视频里的外观、尺寸、使用动作与故事逻辑。
7. 若设计换版，计划中的后续引用提示复核；已经生成的 Run/Take 保留当时的真实图像输入快照，不静默覆盖。

### 4.1 背景与照明

道具图板是用于认清物品的**中性美术参考**。建议使用干净、不干扰外观判断的背景与均匀灯光，确保材质、刻痕、颜色和边缘可辨。**不强制所有道具纯白底**，因为透明玻璃、金属、黑色材料可能需要适合识别轮廓的中性反差背景；不把惊悚、雨夜、强彩光等导演现场氛围预先烙在稳定道具设计里。

## 5. 文字与微小细节：特别防止“看上去有字”但内容错误

信件、戒指铭文、证件号码、密码、徽章、表盘与刻度等有时候就是影片的关键信息。

- 关键信息的**准确原文、拼写、符号、位置和含义**应作为剧本/道具的可核查事实保存，而不是只藏在图片像素里。
- 图片模型生成的字符、形状、数值可能错误。重要时必须在**真实整张图板**中放大审阅，无法读清时不能宣称重要文字已经正确锁定。
- 如果图板不能可靠表现小字，可以在后续第 4 区单独准备用于具体特写 Shot 的**镜头级可验证画面**，或采取经批准的美术修正策略。这不意味着给同一道具创建四张独立正式设定图。
- 道具图片的文字 QA 通过，也不能说明生成视频中的文字一定正确；最终由第 6 区看真实 Take 验证。

## 6. 道具 1+3 图板语义生成模板（待实测）

> 为电影【Film】中的剧情关键道具【Prop ID / 名称】及其正式可见状态【State】生成**一张完整的“上方大主图 + 下方三张辅助细节图”的 1+3 道具美术参考图板**，不是四个不同物件或四个电影镜头。  
> 稳定的物理事实：【形状、材质、颜色、相对大小、使用磨损、重要固定构造、已采纳设计版本】。  
> **上方主图**：从【能认清全貌的主观察角度】展示**同一件完整道具**，轮廓、材质、尺度清晰。  
> **下方左**：【按道具选择的反面/侧面/第二结构视角】，必须与主图物理一致。  
> **下方中**：【对剧情最重要的结构、铭文位置或识别细节】，不能无端发明符号与文字。  
> **下方右**：【尺度/厚度/功能关系/必要固定细节】，默认不加入人物、角色手部或额外剧情动作。  
> 四幅图是**同一件物品、同一个可见状态**，不存在材料、形状、图案和磨损位置的互相矛盾；背景干净中性，灯光便于审阅物件；只输出一张可预览的完整图板。对可核查文字仅以项目正式文本为准。

这只是**模型无关的业务语义**，不是已经验证的图片 API 形参；生成的几何与铭文可靠性需要真实样张检查。

## 7. 可工程验收的专业 QA（草案）

| ID | 必须检查 | 失败案例 |
|---|---|---|
| PROP-01 | 识别为故事里**同一件道具**，明确实际剧情用途与 Prop Identity | 一张图板含四把不同款式钥匙 |
| PROP-02 | 按已确认 1+3 交付**一张完整整图**，上方主图清晰，下方辅助图能辨认 | 生成四个互不关联文件或下面三格模糊 |
| PROP-03 | 形状、轮廓、材质、颜色、磨损与关键结构四格一致 | 主图黄铜钥匙，侧图变银色或齿形不同 |
| PROP-04 | 相对大小/尺度可信、物理结构和连接关系合理 | 同款钥匙忽大忽小，开合机构物理不可能 |
| PROP-05 | 剧情关键铭文/字符/刻度**真实可核查** | 提示词中写对了，但图板中是胡乱文字 |
| PROP-06 | 同一正式图板代表**同一 Prop Visual State** | 未开封与已撕开的信封随机混在同状态图板 |
| PROP-07 | 手持方向/使用动作不篡改资产身份 | 换到右手就强制生成另一个 Prop |
| PROP-08 | 主图和辅助视图职责明确、没有多余人物/动作 | 为展示尺度生成整个人物，导致模型将人当参考 |
| PROP-09 | 真正 MediaFile、版本/历史与引用可访问且追溯 | 只有提示词、失效链接、换版篡改历史 Run 输入 |
| PROP-10 | 第 5 区依**具体路由**验证整图参考兼容，第 6 区按真实 Take QA | 图片通过后就假定 H3 能识别四幅画面并持续保持一致 |

**关键门槛**：凡涉及剧情身份的物件被误生为不同实体、关键几何/材质跨格矛盾、重要文字不可核对，不能作为“通过审核的稳定道具参考”。编辑纠正后须重新审查，并不能因模糊相似度或 AI 自述评分就自动放行。

## 8. 与六区及 H3 原生音画的交接

- **第 1 区**决定某道具为什么重要、谁拥有它、何时出现和转移；
- **第 2 区**确定视觉形态、材质、尺寸和每个重要外观状态的**正式图板**；
- **第 3 区**决定人物如何接触/交换/展示道具，以及导演为什么拍；
- **第 4 区**在同一 Shot 的执行设计里编排动作、视线、左右手、时序、道具和相关声音；镜头级关键画面不是道具图板本身；
- **第 5 区**按目标模式合法编译整张图板的引用或提示技术限制，保留模型真实输入与生成结果；
- **第 6 区**观看真实视频检查外观、手指持握、交接动作、关键细节、尺度、音画关系，定点追踪错误来源。

**不假定 MiniMax H3/具体聚合路由能直接理解拼图形式**；必须验证是否会将主图及三个辅助图误解释为四件道具或重复物体。只保存整张正式道具板不妨碍第 4 区针对某个镜头**另建专业分镜关键帧**，两者归属不同。

## 9. 已确认与仍待集中审定的事项

### 已确认（PD-009）

- **P-01 道具重要性分层**：剧情关键道具应有独立正式参考；普通环境陈设并入场景图板，**不要求所有小物件独立生成**。
- **P-02 关键道具交付形式**：一张**上大主图、下方三辅助视图**的完整 1+3 整合图板，不拆为四张正式参考单图。
- **P-03 视角内容方向**：主图呈现完整道具，下面优先为反面/结构、剧情关键细节、尺度/功能；针对钥匙、戒指、信件等不同物件灵活调整。

### 仍为草案或待实测

- **P-04 持续外观状态**：折断、烧坏、永久开封等是否总是需要独立一张该状态整板；不应混淆现有 Prop Identity 与 Shot 持握动作。
- **P-05 关键文字/符号 QA**：具体允许的文字校验/修复方案、质量阈值和审片策略。
- **P-06 图片模型能力**：gpt-image-2 真实中转路由是否有效生成、修订并保持全板跨格一致。
- **P-07 视频模型参考**：MiniMax H3 具体模式是否准确接受一张复合图板并保持单个道具身份。

下一步无需为每一项单独发问。第 2 区的统一出图和下游就绪建议见 [V1.3-11](11-ASSET-PRODUCTION-READINESS-AND-QA.md)；由 [V1.3-12](12-DIRECTOR-SHOT-TO-CLIP-HANDOFF.md)进入第 3/4 区。上述草案和实测问题待阶段性集中审查。
