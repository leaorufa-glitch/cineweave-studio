# V1.3-09｜第 2 区：关键道具资产设计与图片生成规范 V1

> **状态：专业设计草案，待创作者审定；日期：2026-10-10。**  
> 本文件讨论剧情重要道具的视觉身份、图片规范、连续性和下游引用，**不要求所有道具都建立与人物相同的四宫格**。人物已有的 PD-006 规则不发生变更。
>
> 本轮不生成关系图、示意图片、实际模型输出或代码；具体图片模型、视频模型能力均未完成逐模式测试。

## 1. 道具的专业角色：不只是漂亮的小物件

传统影视的道具同时承担故事信息、人物关系、表演动作和画面连续性。对于 AI 影视，重要道具尤其容易在镜头间发生形状、材质、花纹、尺度、文字和手持位置漂移。

第 2 区应定义**这件道具的稳定外观和可复用参考**；第 3 区导演决定道具如何被人物使用、何时被看到；第 4 区细化其真实动作、交接、取放和连续性；第 5/6 区验证实际生成的音画结果是否保持一致。

**建议区分**：

| 道具类型 | 影视意义 | 推荐 V1 资产投入 |
|---|---|---|
| **叙事关键道具**（Hero Prop） | 承载情节信息、角色选择、悬念、身份或转折 | 必须有清晰稳定的正式设计和真实参考图；需要时补角度/细节/使用参照 |
| **连续性关键道具** | 虽不推动核心情节，却反复被手持或处于画面焦点 | 有可追溯的正式外观/状态，依据镜头需要补图 |
| **普通环境道具** | 主要用于场景生活感、美术布置 | 可以纳入场景设计的陈设事实，不必为每个普通杯子/椅子建单独资产 |
| **临时一次性道具** | 只有一个镜头、并非身份/剧情要点 | 允许只在 Scene/Shot/Clip 的文字或场景参考中表达 |

不建议为了“资产库完整度”自动为全片所有小物件建立大量单独图片。

## 2. 道具的业务身份与状态（建议）

| 概念 | 含义 | 例如“旧钥匙” |
|---|---|---|
| **Prop Identity** | 同一件剧情道具，是谁/是什么、在故事中代表什么 | 父亲交给女儿的同一把旧钥匙 |
| **Prop Design Revision** | 稳定可见的形状、材质、尺寸、花纹、颜色、磨损与长期特征 | 黄铜、特定齿形和钥匙头形状、磨损位置 |
| **Reference Media** | 实际生成/导入并正式采用的道具参考图片 | 一张清晰的钥匙美术主参考 |
| **Prop State** | 在剧情某个时刻道具处于什么可见或逻辑状态 | 完好、折断、插在锁里、装在信封内 |
| **Shot/Clip Interaction** | 道具正被谁拿、用哪只手、从哪里移动到哪里 | 女儿右手接钥匙，随即放入口袋 |
| **Observed Take State** | 实际生成片段里确实出现什么 | 生成后钥匙在左手或钥匙形状变化 |

重要：**一件道具的设计版本**不等于它在剧情中“被拿起”“被打开”“被扔到地上”的状态。镜头内动作多数属于 Shot/Clip；真正被折断、烧毁、开封等改变了可见物理形态的事件，可以登记剧情状态并评估是否需要新增状态参考图。

## 3. 推荐 V1 图片交付：一件关键道具先有一个正式视觉锚点

### 3.1 关键道具的最小资产

- **一张当前正式采用的主道具参考图**：能清晰看到形状、颜色、材质、辨识特征；实际存在且可预览。
- **一份简洁的道具识别要点**：与故事有关的材质、相对尺度、老化痕迹、独特轮廓或标记；不强制写大量无意义元数据。
- **必要时的补充参考**：背面、侧面、打开/关闭状态、手持时的真实尺度、关键细节或文字；按导演 Shot 需要出现。
- **关键道具状态记录**：哪一段剧情它完好、转交、损坏、打开或被遗失；**移动/持握不必每次生成新图**。

### 3.2 要不要像人物一样用一张整合多视图图板？

**推荐保留为“可选的关键道具多视角图板模板”，先不作为所有道具强制要求。**

原因：不同道具形态差异很大。钥匙、戒指、信件、箱子、汽车，其最有价值的视图和尺寸差异并不一样。硬性规定所有道具 2×2，可能让一张有用的道具大特写变成四张信息不足的小格子。

如关键道具需要多面识别，可以只保存**一张整合设定板**来管理多个方向（而非强制拆成多个正式资产）：

| 图板位置（仅为备选模板） | 作用 |
|---|---|
| 主要识别角度 | 确定基本轮廓、颜色、材质 |
| 反向/背面 | 保持关键形状、纹理的一致性 |
| 侧面/结构 | 体现厚度、转轴、齿形、开合方式 |
| 关键细节或尺度参照 | 体现角色手持时的相对大小或剧情重要标记 |

是否采用图板、如何安排取决于特定道具。**绝不把人物四宫格的“左下无头”规则迁移到道具。**

## 4. 何时给道具生成新图？何时不用？

| 实际变化 | 推荐处理 |
|---|---|
| 原主参考中的物件几何/材质生成错误 | **修订同一设计版本/产生新候选**，不建立另一个剧情道具身份 |
| 同一把钥匙由父亲移交女儿 | **Shot/Clip 动作与连续性状态**，不因为持有人变化而重新造图 |
| 钥匙由右手换到左手 | **镜头/实际 Take 状态**，不是新道具或新外观设计 |
| 道具被折断、烧焦、开封，形态发生持续变化 | **新增剧情 Prop State**；如果后续多镜头需要则按状态制作参考 |
| 剧情中出现第二把外观不同的钥匙 | **另一件 Prop Identity**，不要拿第一把的设计版本冒充 |
| 道具设计因艺术决定整体换样式 | **正式设计修订**，历史 Run/Take 仍记录旧样式 |
| 只是摄影机拍到背面、俯视或极近景 | 按 Shot 需要提供额外角度/细节参考；不因此新建 Prop Identity |

## 5. 关键道具出图语义模板（草案）

> 请为电影《【影片名称】》中的关键道具【道具名称/身份】生成**一张用于视觉身份与材质审阅的道具主参考图**。  
> 它在故事中的作用：【人物关系、信息或象征意义】。  
> 设计约束：【具体形状/比例/材质/颜色、磨损、固定纹饰、特殊构造】。  
> 尺度要求：【可信的相对尺寸或明确测量要求；未知不编造】。  
> 展示方式：【清晰可辨的主要角度，中性照明，背景尽量不干扰物件识别】。  
> 若必须保持与已有道具一致，以【已选正式图像/设计版本】作为造型来源。  
> 不要凭空追加重要文字、品牌、标识或导致物件身份变化的装饰；不要添加无关的手、额外道具或剧情动作，除非要求某个使用状态参考。

### 对文字、标识、刻字的特殊要求

- 戒指刻字、信件内容、编号、钥匙符号、徽章图案等如果**直接承载剧情信息**，不能只信赖模型随机生成的细小文字。
- 需要保存人工可核查的**正式内容事实**；若图片本身无法准确表现，说明局限并在镜头/道具修订阶段解决。
- 第 5 区不得把“Prompt 里要求了正确字样”等同于真实 Take 已经正确显示。

该 Prompt 只是通用设计语义。具体 `gpt-image-2` 支持的画幅、局部编辑、参考数量及格式，都需要按聚合站实际路由文档与实测核定。

## 6. 视觉和连续性 QA（V1 业务验收建议）

| ID | 检查点 | 失败例子 |
|---|---|---|
| PROP-01 | 关键道具身份与叙事作用明确 | 只有“金属物件”，无法定位对应 Scene |
| PROP-02 | 主参考是一张可访问、清晰、可溯源的真实媒体 | 只有提示词，没有实际图片 |
| PROP-03 | 稳定形状、材料、颜色、磨损/特殊结构可辨 | 同一把钥匙每张图齿形都不同 |
| PROP-04 | 如含多个角度，角度之间物理构造协调 | 背面消失了正面应贯穿的结构 |
| PROP-05 | 相对尺度可信 | 一把手掌大小的旧钥匙突然变成半米长 |
| PROP-06 | 剧情关键文字/符号有正式事实并且经实际审阅 | 剧情关键刻字错误或不可读 |
| PROP-07 | 物件外观与暂时持握/位置状态分离 | 改成右手拿就另建新道具 |
| PROP-08 | 设计换版保留历史引用和已生成媒体 | 新钥匙参考静默替换已经生产的 Run 输入 |
| PROP-09 | 分镜按具体用途选真实参考版本 | 模型编译引用了错误的道具或未发现文件缺失 |
| PROP-10 | 实际视频由第 5/6 区再审查 | 静态参考已合格却直接宣布 15 秒 Take 中手指/钥匙全程稳定 |

## 7. 对场景资产与角色 Look 的联系

**角色 Look**确定人物的标准服装与外观；**场景资产**确定背景空间与陈设；**道具资产**确定独立物件的外观身份。

例如同一把钥匙在雨夜车站：

- **第 1 区**：决定父亲把钥匙交给女儿的戏剧意义；
- **第 2 区**：固定父女 Look、车站美术身份、旧钥匙的形状/材质；
- **第 3 区**：决定交接动作如何表演，是否通过一个长 Shot 保持人物空间关系；
- **第 4 区**：规划“父亲右手递出，女儿右手接过”的真实时序与道具连续性；引用人物完整四宫格及道具主参考；
- **第 5 区**：按 H3 等目标模式实际支持的参考方式编译，保存请求版本；
- **第 6 区**：检查真实 Take 的钥匙有没有变形、左右手是否错乱、戏剧动作是否成立，必要时反馈。

**关键原则**：道具造型问题与“生成中突然变手”不总是同一类故障。不要让第 2 区无限追加图片来代替分镜约束和真实生成 QA。

## 8. 推荐面向创作者的操作方式

资产设计页面中，用户打开某件关键道具时应能：

1. 看见当前采用的**主参考图**及状态；
2. 查看故事里这件道具的重要性及固定外观要求；
3. 必要时要求美术 AI 生成一个明确角度/细节/损坏状态的候选，而不是无意义地多出十张美图；
4. 比较不同候选并正式采纳，保留被替代历史版本；
5. 查看哪些 Scene/Shot/Clip 用了这一设计版本；
6. 从审片问题直接定位该道具，并判断是美术资产设计错误还是视频生成/连续性错误。

普通场景陈设不需要完整道具详情工作流，可直接作为场景布置记录。

## 9. 需要创作者下一轮审定

- **P-01：关键道具交付标准**——推荐一张主参考 + 简洁固定外观说明，真正有需要才补背面/尺度/细节。
- **P-02：多视角图板**——推荐作为可选模板；不强制所有道具 2×2，是否符合用户希望的统一程度需确认。
- **P-03：道具状态变化**——推荐折断/开封/严重损坏时记录剧情状态；普通手持与移动在 Shot/Clip 管理。
- **P-04：道具库范围**——推荐只把关键叙事/连续性物件作为独立资产；普通小物件可以由场景设计表达。
- **P-05：重要文字/符号**——推荐保留可核查的正式内容与实际图像 QA，不保证文本到图片生成后必然正确。

以上尚未作为用户批准决策，不应由 Codex 自动硬编码。
