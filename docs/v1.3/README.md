## 本阶段解决的核心问题

AI Film Studio 不是“按照步骤填完文档，再调用视频生成器”。整个系统必须持续创作和判断：

- **第 1 区**：怎样让 LLM 具备真正的剧作开发和反复打磨能力，而不是只生成格式完整的弱剧本。
- **六区全部**：专业 LLM 如何使用同一影视工程上下文，提供高质量、可审阅的意见，而不接管系统长期状态。
- **第 3→4 区**：导演创造的同一个 Shot，怎样深化为可实现的分镜视听设计和 Clip 计划，同时保护导演意图。
- **第 5 区**：多模型输入编译、真实文件引用、H3 单 Clip 15 秒、原生续接和批量执行怎样保持可靠。
- **第 6 区**：实际 Take 的音画质量怎样反馈回剧本、资产、导演、分镜、生成和成片。

## 已确认约束与待核实事项

**已确认**：六区共同决定作品质量；故事与剧本是创作原点；专业 LLM 贯穿所有工作区；正式项目事实与版本由系统管理；第 3 区创建 Shot、第 4 区完善同一 Shot；Shot 和 Generation Clip 不等同；V1 单次 Clip 时长上限 15 秒；H3 主力、跨模型可扩展；原生续接必须具备真实上游依赖。

**尚未验证**：当前中转站具体模型路由、H3 模式及 Prompt/API 字段、真实 Motion Context 保存与重放接口、视频模型的并发/取消/费用接口、图片模型格式与约束。

本阶段**不指定 Agent 人数、编排框架、技术栈或数据库物理表**；不使用真实 API Key；不发起收费模型调用。

## 下一步审定条件

- 创作者认可第 1 区专业故事开发不被削弱，且 AI 始终可参与六区创作；
- 用户、系统、AI 的权责分明，AI 能提出强有力的创作改进，系统不会丢正式状态；
- 导演、Shot、Storyboard、Clip、Run/Take、Timeline 之间既无重复身份也无不可追踪覆盖；
- 续接和批量任务的失败、换父 Take、版本变化能被明确处理；
- 审片按剧本与导演目标评价实际音画，而非只凭任务完成状态。

**重要：上述文档是设计草案，不意味着当前已有可运行系统。**
