# V1.3-12｜第 3→4→5 区：导演 Shot、分镜与资产绑定的生产交接合同

> **状态：新建集成草案，待创作者集中审定；2026-10-10。**  
> **已确认边界**：第 3 区创建并负责专业 Director Shot，第 4 区**完善同一个 Shot**，不建立竞争性“分镜 Shot”；Shot≠Generation Clip，且允许多对多；H3 为第一阶段主力，V1 每 Generation Clip ≤15 秒；具备真实父 Take/Motion Context 才能标记原生续接。  
> **最新已确认资产形式**：[PD-006 人物](../decisions/2026-10-10-CHARACTER-GRID-LOOK.md)、[PD-007 场景 1+3](../decisions/2026-10-10-SCENE-GRID-STANDARD.md)、[PD-008 声音与语速](../decisions/2026-10-10-VOICE-ASSET-DIRECTION.md)、[PD-009 道具 1+3](../decisions/2026-10-10-HERO-PROP-BOARD.md)。  
> 本文只形成文字业务和验收合同，不确定最终 UI、数据库表、实际 API 字段；不执行生成、代码开发或制作关系视图。

## 1. 核心目标：不是让系统快速造满镜头，而是保护电影表达

影视作品质量优先由**故事冲突与信息安排、导演视点与表演、镜头的动作因果、影像空间连续性、声音与时间节奏、成片整体结构**决定。第 3 区把这些内容落实为导演选择，第 4 区使之在实际模型约束下可执行，第 5 区真实生成，第 6 区以可播放媒体衡量结果。AI 应协助创作者**做出专业判断**，不是以随机“电影感”关键词填充镜头。

**重要**：第 3 区导演不直接等于 H3 Prompt 编辑器，第 4 区分镜也不等于把 Shot 简单切成固定 15 秒视频。要保留编辑与反馈能力，不牺牲角色表演和导演长镜头。

## 2. 第 3 区：Director Shot 该有的最小“专业镜头决定”

| 导演内容 | 应保存的创作意义 | 示例（父女雨夜车站） |
|---|---|---|
| **Shot ID + 关联 Scene/Beat** | 唯一导演镜头及故事位置 | Shot04 对应父亲递出钥匙的戏剧转折 |
| **观众信息与戏剧目的** | 观众在这个镜头发现什么、如何感受 | 保留父女之间的情绪距离，交接钥匙后父亲无言 |
| **表演与调度** | 谁先动作、谁迟疑、视线、站位及动作因果 | 父亲右手递出；女儿先看他，再伸右手接过 |
| **摄影立场与镜头语言** | 景别、机位、构图、运动、切或不切的**原因** | 两人同框、缓慢靠近、22 秒不切 |
| **音画设计** | 关键对白、节奏、停顿、自然声音和环境关系 | 父亲的后半句放慢，雨声和站台远声，最后空白 |
| **不可静默改变约束** | 什么是“导演决定”而不是可随意改的技术细节 | “保持同一连续 Shot，不得为方便生成强加切镜” |
| **镜头审片标准** | 什么结果算保留表达 | 人物距离和动作相对关系成立，交接有情感重量 |

这里不要求用户逐行填满表单：AI 可由已批准 Scene/Beat、资产和创作对话形成**可编辑建议**，创作者只处理关键艺术决定，系统保留 Shot 版本和依赖。

### 专业 AI 的工作方式（推荐）

- 围绕当前 Scene/Beat 解释“为什么拍成这样”，可提出两种有戏剧意义差异的导演方案，而非十种随机滤镜。
- 明确指出当前剧本的因果/人物状态是否足以支撑镜头；需要时建议回到第 1 区。
- 了解第 2 区角色 Look、场景 1+3 宫格、道具 1+3 宫格和 Voice Identity，并把资产作为**已知事实来源**，不能虚构尚未存在的正式文件。
- 第 4 区发现能力冲突时向导演提出调整理由；**不为符合模型悄悄重写导演镜头意图**。

## 3. 第 4 区：同一个 Shot 的视听执行，不额外复制身份

第 4 区至少完成五件事（可在一个聚合操作视图内完成）：

1. **画面/调度**：每个 Shot 阶段的主体动作、站位、视线、道具持握与物理空间关系，必要时生成镜头级 Storyboard Media；
2. **视听时间**：对白原文与角色、当前**表演语速**和独立**停顿**、环境/道具声、重要动作的时序和重叠/先后约束；
3. **资产引用**：Character + Look + 其**完整人物宫格版本**；Location + Environment State + **完整场景 1+3**；Prop + Visual State + **完整道具 1+3**；Voice Identity + 基准语速/真实样音及本镜头的表演覆盖；如引用失效须显式报错；
4. **起止连续性**：片段开始/结束的角色位置、手持道具、衣服临时状态、场景地标和动作/声响是否接续；
5. **Generation Clip 的组织**：根据 Director Shot 的真实分段、切镜和实际模型能力规划生成单位，**每 Clip 不超过 15 秒**。

**重要区分**：人物/场景/道具的图板**不是“分镜关键帧”**；第 4 区为执行某个 Shot 创作的镜头画面另有 Storyboard Media 身份。目标模型是否能使用图板与 Storyboard 组合，等第 5 区根据**具体模式**核对。

### 第 4 区的最小时间条目

每个关键视听事件至少可表达：**所在 Shot/Clip、相对时间范围、主体、动作或台词原文、表演/摄影/声音意图、所需资产身份与版本、开始状态/结束状态、相关约束及可调整程度**。具体字段和表现形式由 V1.5 设计，不能提前指定单一 UI 时间线结构。

不把 AI 自然语言对话视为已保存的正式时间条目；要由系统显式采纳/存储版本，同时允许用户直接调整。

## 4. Generation Clip 不是导演 Shot（两种一开始就必须跑通的场景）

| 场景 | 专业镜头决定 | 第 4 区计划 | 系统不得做什么 |
|---|---|---|---|
| **一个 Clip 多个 Shot** | Shot01 6 秒，Shot02 6 秒，导演明确切镜 | 合为一个 12 秒多镜头 Clip，保留两段 Shot 的独立身份/导演目的、切点与声音 | 把两个 Shot 变成一个新的“导演镜头”，或假设模型一定准确切两次 |
| **一个 Shot 多个 Clip** | Shot04 **22 秒连续镜头、不切** | B1 12 秒 + B2 10 秒，仍同一 Shot；如果实际路由和父 Take 支持，B2 计划原生续接 | 因为 15 秒限制擅自在第 12 秒加一刀，或仅凭 B1 Clip 名称假称已有 Motion Context |

B2 使用真实父 Take、父 Run、已保存 Motion Context，且父结果经适当 QA 才可启动实际续接。若续接模式不支持，则在第 3/4 区提出创作和技术替代方案，不能把尾帧衔接标成原生续接。

## 5. 从资产到模型的最小交接包（业务语义，非 JSON Schema）

一条待执行 Generation Clip 必须能让第 5 区直接知道：

| 类别 | 必须能解析的内容 |
|---|---|
| **作品来源** | Film、Scene/Beat、Director Shot ID/版本、Clip ID/版本、Shot-Clip 时间映射 |
| **导演意图** | 镜头想表现什么、哪些要求不可改、为何切/不切，风险接受边界 |
| **视听事件** | 时长（≤15s）、动作顺序、景别/运镜、对白原文、说话者、表演语速与停顿、环境/拟音/音乐意图 |
| **视觉身份** | 人物角色身份/Look/整张四宫格版本；场所/环境状态/整张 1+3 场景板版本；道具身份/视觉状态/整张 1+3 道具板版本 |
| **声音身份** | Voice Identity、基准语速和本场/本句覆盖、正式样音有无及当前模式兼容性；不虚构 voice/speed API 字段 |
| **连续性** | 开始/结束站位、手持道具、衣服状态、行动方向、镜头内可见地标、声音连续性 |
| **生成方案** | 独立/参考引导/真实原生续接候选；目标模型能力要求、依赖关系和可能的替代路径 |
| **QA 目标** | 具体能通过实际 Take 验证的表演、画面、音画和连续性标准，以及不可接受缺陷 |

第 5 区根据真实模式能力把上述**业务完整性**编译成合法调用，落下**不可变的 Compiled Input/Run 快照**。若目标 H3 不接受复合图板、声音样音或复杂时序，不允许编译器自行创造假字段，也不允许悄悄拆成四个正式图片后假称还是同一资产协议。应报告具体不兼容项与可用的专业解决方案，再由人/专业 LLM 评估是否改变制作方案。

## 6. 可检验的“父亲递钥匙”22 秒方案

**资产输入**：父亲当前正式 Look 宫格、女儿当前正式 Look 宫格、车站雨夜完整 1+3 图板、完整旧钥匙 1+3 图板；父女声音身份（含独立基准语速和样音实际就绪状态）。

**第 3 区**：导演确认“父女同框的 22 秒连续表演，关键情绪由沉默和迟疑完成”，这是**一个 Director Shot**。长时间的情绪与空间控制是艺术选择，而不是需要从模型最大时长反推的结构。

**第 4 区**：细化真实事件次序（例如父亲开口、放慢语速、递出钥匙；女儿先迟疑再接过，随后留有沉默），分别规划 B1 12 秒、B2 10 秒两个生成单位。事件在两段间的确切边界留待创作者/导演确定；**不编造每句台词、每秒动作分配已获批准**。

**第 5 区**：检查 B1 实际模型模式与整板、声音是否兼容；B1 Run 完成且父 Take 符合要求并真实取得 Motion Context 后，才能认为 B2 的原生续接“可执行”。若条件不成立，显示计划与限制，而不是声称续接完成。

**第 6 区**：实际播放 B1/B2，核对脸/服装、站台地标、钥匙形状/在谁哪只手、父女音色/语速与情感表演、连贯运动，以及拼接点是否真正无叙事剪辑。如果某项失败，把**具体时间码 + 资产版本 + Run/Take 来源**反馈相应工作区。

## 7. 业务验收：为未来工程准备，不代表当前已运行

| ID | 测试场景 | 必须成立 |
|---|---|---|
| HANDOFF-01 | 导演新建 Shot，分镜继续细化 | **相同 Shot ID**，第 4 区可改变执行细节但不能无授权改变已定的导演意图 |
| HANDOFF-02 | 一个 Clip 关联多个 Shot | 仍有各自镜头目的、切镜边界与来源 |
| HANDOFF-03 | 22 秒连续 Shot 分 B1/B2 | 同一 Shot 不中途强制切镜；Clip 各 ≤15 秒，续接有真实父上下文才能执行 |
| HANDOFF-04 | 使用三种正式整图资产 | 第 4/5 区能解析当前采用整板与不可变版本，**没有四张拆分单图依赖** |
| HANDOFF-05 | 导演修改某句语速或停顿 | 改的是台词表演，不会改 Voice Identity 基准语速 |
| HANDOFF-06 | 角色换 Look、车站雨夜改版、钥匙损坏状态变化 | 相关计划需要复核、历史生成快照仍可追溯，不误用不同时段的状态 |
| HANDOFF-07 | H3 当前目标路由不能理解某整板/语音参考 | 生成前明确报告模式不兼容与专业替代，不能静默丢输入或假报支持 |
| HANDOFF-08 | AI 认为 Shot04 太难做，建议增切镜头 | 必须形成导演改动提议，不能由分镜/编译器悄悄更改 Shot |
| HANDOFF-09 | 实际 Take 钥匙换手或父女音色变了 | 第 6 区据真实音视频记录时间码和来源，并准确向上游反馈 |
| HANDOFF-10 | 一次生成不合格但输出文件存在 | 区分“模型成功”“媒体可播放”“电影质量通过”“可用于成片”四个不同判断 |

## 8. 本阶段不再逐项确认的东西

不会对每个表单栏位、标签名字、具体页面三栏布局、数据字段拼写和非关键默认数值分别发起“是否同意”的对话。集中审阅的**重大决策**仅包括：

- **是否保持导演 Shot 的创作权限，不允许分镜或 H3 编译重写导演意图**（此原则此前已确认）；
- **如何在多镜头/长镜头跨 Clip 时保留故事、真实音画与连续性**；
- **若目标 H3 路由不兼容整图参考或原生续接，用户希望系统先停下提示，还是允许有授权的专业替代路线**（未批准）。
  
其他细化参数全部进入待验证/待评估清单，等待阶段性设计审查，而不是每完成一项就单独开一个决策回合。
