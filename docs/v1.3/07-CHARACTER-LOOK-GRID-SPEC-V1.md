# V1.3-07｜第 2 区人物 Look 与四宫格资产生成规范 V1

> **状态：详细规则草案，待创作者审定**；日期：2026-10-10  
> **已确认内容**：见 [PD-006 人物 Look 一致性四宫格决策](../decisions/2026-10-10-CHARACTER-GRID-LOOK.md)。  
> **本文新增建议**：Look 何时新建/修改、人物图 Prompt 模板、质量验收、系统状态与使用方式；尚未获用户逐项确认。  
> 项目约束：只做文字和业务规范，不生成关系图、示意图片、应用代码，也不调用收费模型。

## 1. 目标与范围

第 2 区的正式人物图片并非四张不同用途的散图，而是**一个角色某一套服装装造（Look）对应一张完整 2:3 竖版 2×2 一致性宫格**。它为导演与视频生产提供稳定的角色身份和装造依据。

- 适用所有**正式登记的人物资产**，不仅限于主角或配角。
- 一个 Character / Person Identity 可拥有多个 Look；相同 Look 不因进入新 Scene 而复制出新身份。
- 每个 Look 在同一时点只有**一张当前正式采纳的完整宫格**；生成时的候选或被替换的历史版本可追溯，但不同时作为多个“当前正式图”。
- **禁止自动生成并管理四张拆分单图**；跨区正式资产引用以整张宫格为单位。
- 不把人物图片规范强加给场景、道具、声音；它们的专业规范另行设计。
- 不把每次情绪、手持道具、身体动作都当成新的 Look。

## 2. 已确认的四宫格固定构图

| 位置 | 固定视图 | 关键要求 |
|---|---|---|
| 左上 | 正面头肩/脸部特写 | 完整头顶、面部清晰、中性表情，用于身份判断 |
| 右上 | 严格 90° 侧面头肩特写 | 与左上头部比例、镜头距离、光照和背景协调；不是 45° 或 3/4 脸 |
| 左下 | 无头正面服装全身图 | 正面，从颈部以下直到鞋底，**头部不展示**，身体及服装完整，不出现伤口/断面 |
| 右下 | 完整背面全身图 | 背面从头顶到鞋底完整显示，头发、衣服背面和轮廓清晰 |

整体：**2:3 竖幅，清晰 2×2 四区域，白底或浅灰白无缝棚拍，干净均匀的中性照明，同一人物及同一 Look，无道具持握或剧情动作**。

- 上面两格应采用彼此一致的头像视觉尺度；下面两格应采用彼此协调的身体尺度，脚底位于同一水平线。
- 上下格因为头像近景与身体全身展示，**不要求完全相同拍摄距离**，以免导致不可能的构图要求。
- 左下的“无头”是**服装参考的构图方式**，不是角色断头的剧情或暴力画面；不得生成伤口、颈部断面等内容。
- 建议不加文字标签、水印、复杂分割装饰、场景背景或多余人物，以保护参考清晰度。这是**待审定的出图细化建议**。
- 单张整图应清晰到可以审阅面部与服装细节；最终像素规格和裁切算法必须基于实际图片模型能力验证后确定。
- 同一个 Character 的不同 Look 须保持身份一致；图片风格可以服从作品（写实、动画等），但四宫格参考本身保持中性的影棚展示逻辑。

## 3. 最关键：Look 的业务定义（推荐，待确认）

**Look 是同一角色在故事中一种可识别、需要稳定复用的服装/妆发/外观组合。**

Look 不是：
- 每一张 AI 生成图片（同一 Look 可有候选与版本历史）；
- 每一个 Scene 或 Shot（多个 Scene/Shot 可以使用同一 Look）；
- 每一种即时表情、身体动作或手持道具状态；
- 改错/提高图片品质就必须新增的一个新 Look。

建议 Look 的业务身份至少对应：**Character ID + Look ID**，在其下选择一个当前正式 Grid Asset Revision。需要保留作品关联和采用的来源信息，但不在本阶段定具体数据库字段。

### 3.1 什么时候应该**新增 Look**

建议当角色在故事中出现**具有明确视觉区分、需要被后续镜头稳定维持的装造组合**时新增：

| 变化 | 判断 | 示例 |
|---|---|---|
| 更换服装主体 | **新 Look** | 日常衬衫 → 雨夜风衣；校服 → 正式礼服 |
| 外穿层显著变化且形成稳定剧情造型 | **通常新 Look** | 穿上厚大衣并在若干镜头持续出现 |
| 发型/假发或重要妆容发生创作性变化 | **新 Look** | 日常短发 → 剧情中固定的长假发造型 |
| 角色的年龄/年代阶段发生明显变化 | **新 Look（同角色身份）** | 青年时期 vs 老年时期 |
| 戏剧性变装/伪装造成身份识别外观明显不同 | **新 Look** | 便装 → 警察制服或遮脸伪装 |
| 一个剧情事件后形成**长期持续且明显改变的外观造型** | **评估新 Look** | 制服严重破损、需要在多个后续场景固定呈现 |

### 3.2 什么时候**修订同一个 Look**，而非新建

同一个服装/妆发概念尚未改变，只是在改善描述或图像一致性：

- 面部五官前后不一致，重新生成更符合角色身份的四宫格；
- 90°侧脸画错、左下出现头部、背面方向错误、衣服细节幻觉；
- 设计师决定**纠正**尚未采纳方案的颜色、纹理、服装尺寸、领口或鞋型，但剧情中没有增加一种新的穿法；
- 提高画质、修复手部、重新调整中性灯光背景。

**版本原则（建议）**：这些操作可产生同一 Look 的新候选或新修订；用户采纳后旧版转为历史，仍只有一张当前正式宫格。不能修改已经被 Run 引用的历史媒体文件而保持旧版本 ID 不变。

### 3.3 什么时候只是**剧情/镜头状态**，无需自动新建

- 情绪：开心、犹豫、哭泣、愤怒、疲惫表演；
- 姿态：坐下、行走、奔跑、转头、举手；
- 手持或交接道具：握钥匙、拿杯子、放下手机；
- 短暂天气变化：被雨淋湿、衣领暂时沾水、风吹发丝；
- 普通光照变化：白天/夜间、逆光/暖光/冷光、室内/室外；
- 拍摄角度/景别变化：特写、全身、侧面、仰拍、俯拍。

这些应优先以 **Scene/Shot/Clip 的 Planned Continuity State** 或表演/摄影/环境要求表达；实际 Take 的差异由审片记录。**不意味着上述变化永远不能产生新 Look**：如果衣服破损/湿透被设定为长时间保持的固定造型，并需在许多镜头重复，它可以依专业判断升级为新 Look。

### 3.4 最简单的判断方法

按顺序问三个问题：

1. **是不是在故事中出现了真正不同的服装/装造，而不是镜头角度、情绪或动作？** 若否，通常不新建 Look。
2. **这个差异需要多个 Shot/Clip 稳定保持吗？** 若是，通常建立新 Look；若只有一次临时状态，可以仅记录连续性。
3. **是否只是修正同一套造型的生成错误/设计错误？** 若是，修订原 Look 的宫格，不建立新 Look。

注意：这是一套**推荐默认判断**，不是完全自动决定的封闭算法。涉及关键角色外观的艺术判断可由专业美术 AI 提议、用户审定。

## 4. 人物资产创建流程（建议）

1. **确定角色身份**：由第 1 区人物故事事实与第 2 区视觉身份方案建立一致的 Character 目标，避免换衣服即换脸。
2. **提出 Look 需求**：从实际 Scene/Beat、服装变化及导演意图提炼必要 Look，而不是为每个镜头自动建一个。
3. **定义一张完整宫格的创作要求**：填入角色固定身份、这一 Look 的服装/妆发、统一的构图与照明；不能混入别的 Look。
4. **调用图片生成或导入整张宫格**：用户指定首选图片模型为 `gpt-image-2`，当前**尚未核对路由、实际比例和参考输入能力**；如模式不支持目标构图，必须先明确技术替代策略，不能伪称符合。
5. **专业 AI 与用户检查**：结构合格、角色身份一致、服装真实一致、左下无头/右下背面正确；不合格时对**整张宫格**提出修订，而不是新增四张独立资产。
6. **采纳正式版本**：一个 Look 选择一张当前正式完整宫格，记录来源、版本和验证结果。
7. **绑定到 Scene/Shot/Clip**：跨区共享 Character + Look + 当前采用的完整宫格版本；生成 Run 使用不可变快照绑定实际版本。
8. **后续反馈**：审片发现变脸、服装/发型错乱、背景误导或模型不支持宫格时，定位到资产设计或模型编译问题，提出定点修订，而非无差别新增 Look。

流程可以在授权范围内自动生成草案与候选；不应设置逐步强制通关审批。

## 5. 标准人物四宫格 Prompt 模板（草案）

以下仅是**面向图片模型的语义创作模板**，不是经过 `gpt-image-2` API 验证的官方请求体。影片/角色内容由专业 LLM 基于正式项目版本填入；系统需保留请求与产物来源。

> **生成一张完整的 2:3 竖版、2×2 人物一致性四宫格，四个区域都是同一角色【角色身份描述】、同一种服装装造【Look 具体描述】，遵循【影片美术风格】。背景为白色或浅灰白无缝影棚，均匀中性布光，不要复杂环境。**
>
> **左上：正面头肩近景，脸部清晰，头顶完整，表情中性。**
>
> **右上：严格 90° 侧脸头肩近景，与左上保持头部视觉尺度、背景和光照一致，只改变观看角度；不得生成 45° 或三分之二侧脸。**
>
> **左下：正面服装身体全身参考，头部不展示，仅从颈部以下到鞋底完整呈现服装与身体；没有伤口、断面或奇怪的头部残影。**
>
> **右下：从头到脚完整展示同一角色背面全身、衣服背面与发型背面。**
>
> **下方两格身体比例匹配、脚底位于同一水平线；自然站立、双臂下垂、双手不拿物品。上下四格人物身份、衣服和发型严格一致。不要额外人物、道具、文字标签、水印、复杂分割线或夸张透视。只输出一张完整的四宫格图片，不需要四张拆图。**

### 输入必须明确

- Character 的固定身份外观（符合故事设定的长期面貌特征）；
- 当前 Look 的全套服装、头发、妆容、鞋子、固定配饰；
- 作品美术风格（但人物一致性图保持清晰中性）；
- 如果需要保持已定型角色身份，必须明确引用哪份已有正式宫格，以及实际图片模型是否支持该种参考输入；
- 用户授权与生成费用情况。

不应将“镜头内表演情绪、雨滴、奔跑动作、特殊光影”直接混入中性宫格；那是第 3/4/5 区按剧情和镜头处理的内容。

## 6. 图像验收（不能靠提示词文字声称已通过）

### 6.1 必须人工或可验证质量流程复核

| ID | 检查点 | 未通过示例 |
|---|---|---|
| LOOK-01 | 最终产物恰好**一张完整图片**、2:3 竖幅且为清晰 2×2 | 生成四张分图或比例错误 |
| LOOK-02 | 左上正面头肩，头顶/五官可见 | 正脸被裁断、脸严重失真 |
| LOOK-03 | 右上严格 90° 侧脸，头部尺寸与上左协调 | 3/4 脸、换了鼻型/下巴 |
| LOOK-04 | 左下正面身体，头部不出现、衣服到鞋子完整 | 出现头部、衣服或鞋底缺失 |
| LOOK-05 | 右下完整背面全身，头发/鞋底可见 | 错成正面、只画到膝盖 |
| LOOK-06 | 下排身体尺度协调、鞋底同一基线、双臂自然、无持物 | 高度明显不符、站姿差异过大、手拿道具 |
| LOOK-07 | 同一角色身份和同一 Look 跨四格一致 | 不同五官、服装/颜色/配饰不匹配 |
| LOOK-08 | 干净无缝背景、中性可审阅照明、清晰无多余元素 | 场景图、文字、水印、额外人物 |
| LOOK-09 | 使用的参考文件、产物版本、模型与状态可追踪 | 只能看到图片，没有正式身份与来源 |
| LOOK-10 | 第 4/5 区使用**整张正式宫格**引用，未生成四份持久拆图 | 分镜自动创建四个独立资产而丢失 Look 关联 |

### 6.2 真实模型适配，必须另外验证

- 图片模型是否直接支持 **2:3** 输出、参照图片和局部修订；若不支持，如何不拉伸/裁坏角色而满足产品出图标准。
- H3 的不同真实路由是否接受宫格整体作为人物参考、是否会误解为四个人或四镜头；不能在未实测前保证。
- 若某视频路由不能直接有效利用宫格，系统应明确标记不兼容/需方案调整，**不能擅自把四格拆分、入库并宣称仍遵守本用户规则**。
- 生成整图的实际角色一致性需要通过真实图片和后续 Take 验证；视觉检查不能保证未来全部视频都不变脸。

## 7. 最小业务对象与来源建议（尚非数据库 Schema）

| 概念 | 含义 |
|---|---|
| Character Identity | 角色是谁；在剧情及不同 Look 间稳定 |
| Look Identity | 该人物的一个明确服装/妆发外观组合 |
| Grid Candidate | 一次完整四宫格生成/导入候选；不等于正式版 |
| Adopted Grid Revision | 当前正式采用的**一张整图**及其不可变来源与历史 |
| MediaFile | 上述正式/候选宫格对应的真实图片文件及技术属性 |
| Scene Appearance Selection | 剧情中某一段使用哪个 Look；一个 Scene 有换装时可有多个状态段 |
| Shot/Clip Asset Binding | 当前镜头/Clip 计划引用哪一个 Character、Look、正式宫格版本 |
| Appearance/Continuity State | 额外的动作、道具、光线、湿度、衣服临时状态等，既不替代 Look，也不强制触发新建 |
| Generation Input Snapshot | 第 5 区执行时固定具体 Grid Revision 和模型请求，防止未来换装回写历史 |

允许一个 Look 在升级版本后只显示一张当前正式图，旧媒体保留为历史证据；禁止因删除旧版本而破坏已付费生成的引用。

## 8. 与第 3/4/5/6 区交接

- **第 3 区（导演）**：选择当前 Scene 内角色的正式 Look，决定实际表演、光线、摄影和换装的戏剧意义。
- **第 4 区（分镜）**：按同一 Shot 的执行设计引用 Character + Look + **整张宫格**，补充镜头内动作/环境/暂时状态；不复制人物身份，不创建四个子图。
- **第 5 区（生成）**：依据实际模型能力编译目标请求；需要说明图片已存在、是否支持整张宫格参考、最终所用版本与模式。历史 Run 快照固定。
- **第 6 区（审片）**：检查真实 Take 的脸、服装、妆发和状态是否符合所选 Look；有问题可以反馈至第 2 区，也可以指出第 4/5 区的绑定或生成问题。

## 9. 专业争议与待确认

当前已确认“所有正式人物，一个 Look 一张整图四宫格，不拆分单图”。以下由创作者下一次审定：

1. **Look 新增标准**：穿搭/发型/妆容明显且持续变化新建；同 Look 的图像修正仅修订；瞬时情绪/动作/道具为 Shot/Clip 状态。
2. **受损或湿透等持续状态**：默认先作为剧情状态；只有显著、持续、跨多个镜头重复时可升级成新 Look，而不是逢雨必新建。
3. **是否允许同一 Look 的历史候选**：建议可以保留历史，**同时只有一张当前正式整图**，不产生四张拆图。
4. **脸部跨 Look 一致性核查**：建议用已有正式 Look 做身份锚点；需要先核实图片模型的参考能力。
5. **图片输出细节**：固定图片像素、侧脸朝向、网格线宽和背景灰度先不随意定死，待真实生成质量对比后选择。
6. **整张宫格与 H3 的兼容性**：必须真实验证；不把“用户希望一张图”误当成“每个模型必然接受一张四宫格”。

**下一步推荐**：创作者先确认第 3 节 Look 新建/修订/状态判断规则；之后开展场景、关键道具与声音的同等专业但不同结构的资产规范。
