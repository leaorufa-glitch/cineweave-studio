# V1.3-14｜第 6 区：真实审片、Take 选择、轻量时间线与成片交付 V1

> **状态：综合业务和交互设计草案，待创作者集中审定；2026-10-10。**  
> 已确认方向：**轻量但真实**的审片和成片，不做完整 Premiere/DaVinci 级 NLE；必须能观看/听见真正生成的媒体、比较 Take、标注问题、以非破坏性方式组成可播放影片并真实导出。  
> 来源：[V1.3-05 模型编译与媒体 QA](05-MODEL-COMPILERS-AND-QA.md)、[V1.3-13 生成生命周期](13-H3-GENERATION-ENGINE-AND-RUN-LIFECYCLE.md)、已有 V1.2 Shot/Clip/Timeline 设计草案。  
> 本文只做设计和未来验收；没有真的生成、播放、导出任何视频。

## 一、专业审片的目标：真实影片是否成立，而非模型“成功”

第 6 区不是产物浏览器。创作者必须能判断每个 Take 是否真正完成导演目的、是否存在身份/空间/道具/声音失真、是否与周围镜头连续，并决定是**采用、剪辑处理，还是回到更合适的工作区返工**。

建议将检验明确分成五层，不用一个“通过/不通过”字段掩盖责任：

| 层次 | 检查证据 | 主要判断 |
|---|---|---|
| **A 媒体技术就绪** | 本地/托管真实视频文件、解码/音轨/实际时长/画幅/帧率 | 能否被播放器和成片系统真实使用 |
| **B 资产一致性** | 正式人物 Look、场景 1+3、关键道具 1+3、Voice Identity 及实际 Take | 人脸/服装、空间结构、道具形态/关键文字、音色是否与设计一致 |
| **C 镜头创作质量** | 第 3 区 Director Shot 的戏剧目的、导演/表演/摄影约束 | 情绪与潜台词是否表现、动作是否有因果、摄影选择是否成立 |
| **D 跨 Clip 连续性** | 时间相邻的两段实际 Take、起止状态和真实声音 | 动作方向、站位/手持、雨量、声音/语速、是否突变；真续接是否有实际无缝效果 |
| **E 成片整体性** | 真实可播放 Timeline 与导出结果 | 结构、信息分配、节奏、情绪推进、声画衔接与影片完整性 |

**不允许**“Prompt 写得很清楚”“Run 远端 succeeded”“做了多模态模型视觉分析”直接替代真实播放/试听检查；专业 AI 可能会误判，应保留可纠正的观察与用户最终判断。

## 二、最小专业操作界面（不重建重型 NLE）

### 2.1 三个主要工作状态

1. **Clip/Takes 审片**：按 Scene/Shot/Clip 导航，播放真实媒体，查看导演目标和使用的正式资产版本；在同 Clip 的多个 Take 之间切换/对比，标注问题与采用。
2. **片段组合/轻量时间线**：从已选 Take 裁出需要的引用区间，按影片顺序组合，少量必要声画衔接、原生现场音保留与可选补音；可以预览当前整片。
3. **成片验证/导出**：在明确的影片范围和输出参数下 Render，下载/播放真正导出的文件，做技术+内容检查，并保留 Render 的源 Timeline Revision。

这三种状态共享影片、Shot/Clip/Take 身份，不因为切换页面而复制媒体或丢审片意见。

### 2.2 建议显示的信息

| 区域 | 核心内容 | 用户能执行的动作 |
|---|---|---|
| 播放器 | 真实画面+声音、时间码、播放/暂停/快进/速度控制（仅试听/审看） | 定位真实问题、逐段看片/听音 |
| 当前镜头目标 | Director Shot 的不变量、正式剧本对白、人物/场景/道具/声音参考 | 对照计划判断差异；跳回对应工作区 |
| Take 候选 | 同 Clip 的多个候选真实媒体与来源 Run、模型/成本、评注 | 切换、对照、选为当前采用或保留备用 |
| 专业审片 | AI 辅助提问/观察和用户笔记；分类为事实、艺术判断、建议 | 创建带时间码/证据的评注、采纳/驳回 AI 诊断 |
| 轻量时间线 | 当前使用片段、来源 Take、实际持续时间、必要声画衔接 | 拖放排序、入出点、少量转场和音量/声音衔接 |
| 导出 | Render 状态、输出文件、技术参数、验证与版本 | 提交 Render、试听观看实际成片、再次修订 |

## 三、Take 与正式采用：别强制只留一个结果

- 同一 Clip 可有多个 Run/Take，任意一个被选为当前电影版本的**采用候选**，其他候选仍在历史库；不覆盖源文件。
- 采用的是**该 Take 源媒体文件及关联 Run/资产/导演计划版本**，不是把整个 Clip 计划“修改为该视频”。
- 第 6 区可“暂选后试剪”；最终导出所用的 Timeline Revision 是另一个显式版本，支持比较历史剪辑版本。
- 原生续接的父 Take 如果被改选，依赖旧父 Motion Context 的子链必须标明归属并提醒当前剪辑版本是否还相容，不能擦除原 B2 视频。
- 用户可以为了艺术效果保留某个技术有小瑕疵但表演出色的 Take；记录已知缺陷和选择理由。**重要技术损坏或错误剧情信息不能在未提示下直接标为合格**。

## 四、审片问题：必须有时间码和可执行返工归因

每个专业反馈应能表示：**Film、当前 Timeline/Clip/Take、真实媒体时间范围、观测现象、相关正式剧本/Shot/资产版本、严重程度、创作影响、疑似根因及返工去向**。

| 实际观察 | 常见责任层级 | 优先处理方向 |
|---|---|---|
| 角色动机和转折在影片里缺失 | **第 1 区剧作**或前面镜头的信息安排 | 回到 Scene/Beat 改故事或对白，不无限靠换一个风格 Prompt |
| 对白正确但人物表演不符合导演目的 | **第 3 区**表演导演或第 5 区模型执行 | 分析是否要修正表演意图或重新生成 |
| 女儿和父亲的脸、Look 明显错误 | **第 2 区**视觉身份/Look 或第 5 区参考编译/生成 | 核对真正送入的整板与模型模式，避免无限换资产 |
| 候车棚出口与长凳相对关系前后冲突 | **第 2 区**空间事实 / 第 4 区镜头方位 / 第 5 区视频生成 | 定位发生于哪个真实 Take 区段 |
| 钥匙变成不同物件、从右手跳到左手 | 第 2 区道具设计 / 第 4 区动作连续 / 第 5 区模型结果 | 分清稳定外观与实际动作两个错误来源 |
| 人物声线漂移、语速或停顿不符合导演要求 | **第 2 区**Voice Identity，**第 3/4 区**表演节奏，或**第 5 区**音画效果 | 用实际音频证据定位，不能只看 Voice Prompt |
| B1→B2 的长镜头突然闪切或镜头运动中断 | 真实续接链/模型行为、Clip 边界、分镜规划 | 核对 Motion Context 真实父来源，再考虑镜头重规划 |
| 旁白、雨声与对白音量打架 | 第 3/4 区视听设计 / 第 6 区轻后期 | 优先在非破坏性声音衔接中解决，必要时回源 |

系统/AI **可以提出专业根因假设**，但不能保证每个失真只有一个确定原因；应通过真实版本、真实编译请求和真实视频证据逐步定位。

## 五、非破坏性轻量时间线：只做完成电影所需的剪辑与声音

### 5.1 核心建议

**推荐 V1 保留**：

- 按已采纳 Take 创建 `Timeline Segment`（引用源文件以及 **source in/out** 区间，不修改原 Take）；
- 调整 Segment 顺序、入点/出点、故事节奏；支持必要的简单硬切、少量淡入/淡出、合理声音交叠（如 J/L Cut）的可预览效果；
- 保留 H3 原生画面与音轨作为默认来源；可调节片段音量、基础均衡衔接、必要的环境声/关键道具声或配乐参考；
- 声音外补/替换只在确有电影意义并且用户批准的情况下应用，不预设“每条 H3 原生台词都必须被外部 TTS 重配”；
- 时间线有明确 Film、正式 Scene/Shot 的联系，并显示哪个片段来自哪个 Clip/Run/Take；
- 可以实际 Render 和输出用户选择的交付视频，保留输出来源；
- 如声画需要独立修正，应保留原音轨与编辑操作的非破坏性关系，不虚构从 H3 合成视频中已得到干净人声/环境声分轨。

**V1 不建议先做**：任意多轨专业 DAW、多机位实时混剪、复杂节点调色、三维跟踪、完整 VFX 合成、全部高级字幕动画、与完整 NLE 软件竞争。V1 的优秀短片可以采用轻量工具完成，但不应牺牲对白可听性、镜头顺序、节奏与稳定真实导出。

### 5.2 Timeline 领域语义（非数据库表）

| 概念 | 含义 |
|---|---|
| **Timeline Revision** | 某个电影正式/试剪版本的整体片段顺序和声画配置 |
| **Timeline Segment** | 一次使用的真实 Take 源媒体与具体 in/out 区间，可以多次使用同一 Take |
| **Audio Treatment** | 片段音量、淡入淡出、声音覆盖/交叠的非破坏编辑指令 |
| **Transition** | 简单硬切、合法淡变等，保持可预测和真实音画同步 |
| **Render Job** | 对一个固定 Timeline Revision + Render Profile 的实际导出任务 |
| **Rendered Media** | 真正生成、可播放/可下载并通过技术检查的正式影片文件 |
| **QC Review** | 既可以对应 Take，也可以对应 Timeline/Rendered Media 的带时间码问题 |

建议无缝使用实际输入帧率/采样率进行精确时间码映射；**不把不同视频的标称 15 秒当成精确实际时长**。跨视频的时间轴需要处理真实帧率、尺寸、声道和时基差异；最终由已选 Render Profile 统一。这是后续工程方案的重要验收项。

### 5.3 音频：原生音画优先，但不舍弃可听度

- 尽量保留 H3 原生音画优势：台词、气息、环境和动作音天然与画面同时生成。
- 音色稳定性、**基准/表演语速**、句间停顿和跨 Clip 声音接续由真实监听判定；必要时优先重新编译/再生成，而不是机械拉伸声波造成口型错误。
- 环境声音与配乐不应盖住关键对白；第 6 区允许简单音量/淡变处理和补入有许可的参考声音。
- 仅在真实拥有分离人声/环境音素材时才允许按独立 Stem 处理；不能假装某模型返回 MP4 就天然有多轨干声可自由单独编辑。
- 假如重新配音/单独音频生成是最合理的专业方案，必须明确原生路线不足之处、口型风险和新增授权/成本，不能未经用户选择静默改为全片 TTS。

## 六、从 22 秒“父女钥匙长 Shot”到成片

**已批准的艺术要求**：导演 Shot04 是**22 秒不切镜**，第 4 区规划 B1 12s + B2 10s。第 5 区有真正可追溯 Motion Context 时才执行 B2 真续接，否则只是等待或返回导演评估。

第 6 区从实际生成的 B1-Take 与 B2-Take 预览、在真实交界位置逐帧/逐句检查**运动连续性、脸、衣服、站台背景、钥匙持握和音色/雨声**。若有可见的动作跳跃或音频突变，不能靠把两个文件相邻排列就声称这是一个电影意义上的无缝连续镜头。

如果真的连续性合格，Timeline 可以依次引用 B1/B2 两个源 Take，并将它们作为导演上的**一个 Shot04** 进行成片；影片所有 Shot 顺序来自导演/剧本而非 Run 提交顺序。

## 七、实际导出不只是下载一个 MP4 链接

**建议 V1 的输出行为**：

1. 创作者选择一个固定 Timeline Revision，指定简单 Render Profile（如影片画幅、目标分辨率、输出帧率/音频）。
2. 系统检查所有 Segment 的真实媒体是否仍存在、入出点是否合法、空隙/重叠/时长/声音规则是否一致。
3. 异步实际 Render，保留固定输入来源、错误与结果 ID；不能因为影片总长超过 15 秒就拒绝 Render，**15 秒仅限制单个模型 Generation Clip**。
4. 导出实际文件后技术解码/验证：视频/音轨存在、可播放、输出总时长符合真实时间线、音画同步、画幅/帧率/声道符合交付选择。
5. 真正播放导出成片做最终专业 QC：角色/场景/道具跨场变化是否合理、对白可听度、衔接是否突兀、故事情绪节奏、转场、首尾完整性。
6. 通过后记录 `Rendered Media` 的来源与验收，不宣称“Render 任务 finished = 电影已经通过审片”。

输出质量未通过时应保留 Render 文件、错误与修订关系，而不是覆盖以前合格成片版本。

## 八、可工程验收的最小用例

| ID | 用户操作 | 预期行为 |
|---|---|---|
| REV-01 | 对同 Clip 的两个真实 Take 试听试看 | 能识别模型/Run、输入版本、画面与声音差异并选择使用哪一个 |
| REV-02 | 给 00:04–00:06 的钥匙变形标注问题 | 保存实际媒体的时间码、物件状态及相关 Clip/Take/资产来源 |
| REV-03 | 22 秒导演长 Shot 来自 12s+10s | 两段属于同一个 Shot；审片检查是否实际连续，不因为技术拆 Clip 就新增导演切镜 |
| REV-04 | 选 B1-TakeB 替换 TakeA | 旧 B2 子链标注来源不符，不悄悄宣称与新父完全连续；历史保留 |
| REV-05 | 裁掉某 Take 开头 1 秒 | 修改 Timeline Segment 的引用 in/out，不破坏原 Take 源文件 |
| REV-06 | 同一个 Take 复用两次 | 有两个 Segment 引用同一个源媒体的不同/相同区间，没有复制/改写源媒体 |
| REV-07 | 轻量声音衔接 | 可以调节音量、淡出/淡入和必要 J/L Cut；真实导出可听见预期效果 |
| REV-08 | 原生 H3 音频没有单独人声 Stem | UI 不出现假的“独立人声轨已经生成”，需要单独音频策略时给出明确路径 |
| REV-09 | Render 时某源文件已丢失/过期 | 渲染前报告具体缺失文件，提供重取原结果/替换，不能生成缺段影片假装完成 |
| REV-10 | 导出时长超过 15 秒 | 合法，15s 只限制视频模型单次 Generation Clip，不限制整片时长 |
| REV-11 | Render 进程成功但音轨损坏或总时长错误 | 标为“技术 QC 未通过”，文件保留供排查但不标最终可交付 |
| REV-12 | 审片 AI 没有读取/听到视频，只拿到文字 Prompt | 只能提出待验证的风险假设，不能声称已观察角色/声音实际效果 |
| REV-13 | AI 和创作者对艺术质量意见不同 | 用户可以否定 AI 结论、保留创作选择和决定理由 |
| REV-14 | 80 秒短片完成 | 实际整片可播放/有声、来源可追溯，并能从任意问题跳回对应 Story/Asset/Shot/Clip/Run/Take |

## 九、从设计到实施的依赖

第 6 区的**最小闭环**不依赖完整特效系统，而依赖第 5 区先真正保存可访问的 Take 媒体、不可变生成来源和帧率/音轨信息；第 6 区再构建非破坏性 Timeline、Render Job、媒体 QC 和问题返工链。

应优先用一条完整的 80 秒短片走通“正式剧本与导演 → 素材引用 → H3 模式与 Run → 真实 Take 审片 → 选择与试剪 → Render → QC”，而不是先把所有剪辑工具都设计成专业 NLE 才开始验收。

**结论**：第 6 区要轻量，不等于让用户接受不成片的系统。真正交付是**从真实音画素材可追溯地输出可播放、可审查、有完整叙事的电影**。
