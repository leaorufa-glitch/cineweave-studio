# V1.3-08｜第 2 区：场景资产设计与图片生成规范 V1

> **状态：专业设计草案，待创作者审定；日期：2026-10-10。**  
> 已确认上游：第 2 区是独立的专业美术/视听资产工作区，和编剧、导演、分镜、生成、审片共享统一影视工程；人物 Look 使用每 Look 一张完整四宫格（PD-006）。  
> **重要边界：PD-006 只约束人物，不自动要求场景也使用 2×2 四宫格。** 本文场景图的数量、组合方式、画幅和生成方式全部是待审建议。
>
> 当前只设计文字业务与可验收规则，不生成关系视图、图片、视频，不调用实际收费模型或开始编码。

## 1. 场景资产真正要解决的问题

美术场景不是“一张好看的背景图”，而是同一个虚构空间在不同镜头、时间、天气与表演条件下，仍有可信的地理结构、物件关系和影片视觉风格。第 2 区负责场景美术身份和空间基础，第 3 区决定导演怎么拍，第 4 区落实机位/分镜/视听时序，第 5 区按视频模型能力进行参考编译，第 6 区审查实际空间连续性。

- **艺术**：场景应服务题材、年代、人物处境、戏剧氛围和视觉叙事。
- **地理**：角色入口/出口、门、窗、主要建筑、道具、道路、桌椅等固定地标的**相对位置**要有共同依据。
- **视觉**：材质、比例、老化程度、主色、装饰、天气与灯光应与影片美术基线一致。
- **可生成**：正式图像确实存在且能审阅、能关联资产版本；目标视频模型能否有效引用需独立验证。
- **可修改**：修改场景设计时能追踪哪些 Scene/Shot/Clip/Take 可能受影响，而不删除历史成片素材。

## 2. 场景的正确业务层次（建议）

| 概念 | 表示什么 | 例子 |
|---|---|---|
| **Location Identity**（场所身份） | 故事中同一个物理地点 | 某一座小站台、某间客厅、同一条走廊 |
| **Set Design Revision**（空间/美术设计版本） | 固定的建筑轮廓、功能区、材质、陈设和关键地标 | 出口位于候车棚的一端、站牌/长凳/灯柱的位置 |
| **Environment Look / State**（环境视觉状态） | 同一地点的时间、天气、季节和主要灯光/布置状态 | 雨夜车站、晴天清晨车站、停电后的候车室 |
| **Reference Media**（真实参考媒体） | 具体生成/导入且已选择的图片或图板文件 | “雨夜车站主参考图”PNG |
| **Shot/Clip State**（镜头内状态） | 角色位置、运动、临时物件、当时天气瞬变和镜头光线要求 | 女儿站在长凳前，钥匙落在地上；雨正逐渐变大 |

**不能混淆**：同一地点的正反拍不是两个 Location；雨夜/白天也不自动是两个 Location。换照明不应重置建筑身份。剧情中真的换景、重建房屋或永久修改陈设时再评估新场所或新设计版本。

## 3. 推荐 V1 最小交付：核心场景先有主参考，再按 Shot 补视角

### 3.1 主要／反复出现的场景

**推荐默认**（尚未批准）：

1. **一张正式场景主参考图**：确立空间气质、关键地标、主要建筑/家具、尺度和目标美术风格；真实图像可预览。
2. **一份精简空间事实说明**：从一个固定命名的观察方向描述入口、出口、舞台行动区域、固定道具/陈设及相对位置。采用物理相对关系而非强行规定“所有镜头门必须在屏幕左边”，因为反打镜头左右可交换。
3. **镜头确实需要时追加参考**：典型反打、左右机位、角色背后视角、空间转角或行动局部；不强制每个地点拍满四张/八张。
4. **独立的环境状态**：同一 Location 可有雨夜与白天的正式视觉方案；多张不同状态图片必须共用同一空间基本结构。
5. **明确引用用途**：主参考用于场所身份与总体美术，反打用于某个角度，灯光/天气图用于环境状态，不把所有图笼统叫“场景图”。

**不建议**自动为每个普通场景建立 360 度全部视角、完整 3D 模型或固定四宫格。那些可能增加成本，但未必对实际镜头产生价值。

### 3.2 次要／一次性场景

一次出场、镜头简单、对连续空间不敏感的地点，可以先只保留**一张正式场景参考图及必要空间事实**。若导演或分镜随后发现需要反打/多机位再补足。

### 3.3 如果创作者偏好“一张图审阅完整场景”

可考虑**一张场景多视角整合图板**（与人物四宫格是不同产品模板），把总体、反打、行动区和关键细节组织在一张图里。它可能适合快速审阅，但也可能因格子太小、建筑在不同视角中变形、视频模型误读拼接图而降低实际参考质量。

**这个选择目前待创作者决定**：是以“主参考 + 按需多视角”作为统一 V1 方案，还是给重点场景增加一张整合图板的正式模板；不把未批准的图板方案写成已确认规则。

## 4. 场景图类型和使用职责

| 图片类型 | 解决的问题 | 通常在什么时候需要 |
|---|---|---|
| 主场景建立参考（Master / Establishing） | 地点身份、尺度、陈设与美术方向 | 主要地点建立时 |
| 空间反打／方向参考（Reverse / Direction） | 同一空间转向后的结构和固定地标 | 导演计划反打、转身、环绕运动时 |
| 关键行动区域参考（Action Area） | 人物如何在门口、长凳、桌边、楼梯等区域活动 | 调度涉及真实空间关系时 |
| 细节／材质参考（Set Detail） | 标牌、窗框、地板、年代感、重要装饰 | 细节对剧情或画面可信度重要时 |
| 环境状态参考（Lighting / Weather） | 同一空间在夜晚、雨雪、晴天、烟尘等状态的视觉 | 同场所跨不同剧情条件时 |
| 参考视频（可选） | 真实连续空间与动作运动趋势 | 模型/镜头需要且路由支持时 |

参考图不等于真正建模了物理空间。对 180° 规则/轴线、地图几何、左右动作方向等，系统应该记录**专业约束与观察**，不能仅凭 AI 生成的几张角度图就声称地理一致性得到保证。

## 5. 生成与定型工作流程（可自动协作，但不强制逐步审批）

1. 从正式剧本 Scene、世界事实和导演总体意图识别场景需求，区分同一物理场所与不同环境状态。
2. 美术 LLM 帮助明确场景叙事作用、年代/材质/气质、主要建筑和空间事实；允许参考用户已有图片。
3. 先提出或生成主参考候选，在统一影视工程中留存真实图像和来源；用户选用一个当前正式方案。
4. 如分镜需要反打、行动局部或天气变体，以已选用空间和主参考为**来源**补图；新图不得擅自重新发明地标位置。
5. 对每张真实图片执行结构与艺术检查，记录是否为当前正式参考、替代候选或历史版本。
6. 第 3/4 区可以从 Scene/Shot 跳到场景资产，选择特定**地点 + 环境状态 + 参考版本 + 用途**。
7. 第 5 区按实际路由合法参数编译和执行；第 6 区审查真实 Take 的空间、材质、天气/时间和镜头连续性。
8. 审片或导演发现空间错误时提出定点资产修订或镜头修改，而不是默默覆盖已有 Run/Take。

## 6. 模型无关的场景出图语义模板（待实测适配）

### 主场景参考

> 请为【地点名称】生成**一张可作为电影美术与场景身份参考的环境图片**。  
> 影片世界设定与美术方向：【故事时代、类型、风格、材质、使用痕迹】。  
> 关键空间事实：【入口/出口、固定地标、主要陈设之间的相对位置、行动空间】。  
> 主要观察方向：【从哪里朝哪里看】，所需画面覆盖：【空间范围】。  
> 环境状态：【时间、天气、照明】，同时确保建筑、关键固定物件与其他已选参考保持一致。  
> 图像要清楚呈现建筑空间和主要地标，不要无端添加影响连续性的门窗、重要标牌或家具。  
> 这是一张**场景资产参考**，不是直接用于某个 Shot 的最终电影画面；默认不加入演员和随机叙事动作，除非明确要求。

### 基于主参考补同一空间的其他角度

> 以已采用的【地点 ID、空间设计修订、主参考真实图像】为同一物理场所，生成【具体观察位置/朝向】的参考。建筑结构、入口与固定地标的相对关系不变；只改变观察角度或经确认的环境状态。保持同一美术材质和年代。不得凭空增加新的出口或改变长凳/灯柱的物理位置。

**注意**：这属于业务语义模板，不是 `gpt-image-2` 已经验证的 API Prompt 或 JSON。是否可按真实输入保持不同视角的严格空间一致，需要图片模型实验与人工审查。

## 7. 场景图 QA 验收

| ID | 验收点 | 不合格例子 |
|---|---|---|
| SC-01 | 有明确 Location 身份与对应 Scene/世界设定 | 只叫“漂亮街道”，不能判断与故事哪个地点对应 |
| SC-02 | 主要美术风格、时代、材质与剧本/导演意图一致 | 故事中的旧车站被生成成全新未来科幻站 |
| SC-03 | 固定空间地标相对关系可理解 | 正反机位中楼梯、出口和长凳的空间关系自相矛盾 |
| SC-04 | 图像真实存在，可访问、可预览、来源可追踪 | 只有文字提示词，没有任何可用媒体 |
| SC-05 | 环境状态与地点身份分开 | 仅仅下雨就误建成另一个“新车站”身份 |
| SC-06 | 如生成其他视角，能对照主参考检查空间与材质 | 反打图突然多出第二个大门，建筑风格改变 |
| SC-07 | 用户能看懂各图实际用途 | 所有图片都没有“主参考/反打/细节/天气”的职责 |
| SC-08 | 引用已确认版本并能追踪影响 | 场景换版后，历史 Run 的参考文件被静默改写 |
| SC-09 | 第 4/5 区仅提交目标模式真实支持的图片引用 | 在不支持多图时自动传入全部图或拼接后伪称验证成功 |
| SC-10 | 不以单张图代替真实成片验证 | 视频生成后空间断裂，系统却因图片 QA 通过宣布镜头连续性通过 |

技术质量需实测输出的真实比例、像素、清晰度及生成接口，不在本文编造固定尺寸或能力上限。

## 8. 80 秒案例：雨夜车站

**场所**：同一个小站台。资产主参考先明确站台、候车棚、出口、长凳、照明和站牌等主要地标，并记录它们的**物理相对关系**。环境状态为“雨夜”。

导演希望在 Shot04 保持父女站位距离与镜头连续，因此可能需要确认：人物站立位置、行动区可活动宽度、雨夜反光与车站固定物件在 B1/B2 中是否保持可信。第 4 区可以请求行动区参考；第 5 区若采取原生续接，仍以真实上游 Take/Motion Context 为依据，**不把场景图误当作原生续接上下文**。

若 B1 与 B2 的生成结果出现“同一候车棚两次出现完全不同的大门”，审片可以根据真实视频和地点美术事实判断需修订场景参考、分镜约束还是视频生成策略。

## 9. 需要创作者决定

- **S-01：场景参考的标准组织方式**——推荐“场所身份 + 一张主参考 + 空间事实；其他角度按 Shot 需要补充”，不强制四宫格。是否确认？
- **S-02：关键场景是否需要可选的单张多视角整合图板**——推荐作为审阅增强，先不强制；需实测能否有效作为视频参考。
- **S-03：天气/昼夜变化**——推荐作为同一场所的环境状态，几何变化才触发空间设计修订，不为每次光线变化复制新 Location。
- **S-04：场景主参考画幅**——建议按场景宽度、空间和最终镜头灵活选，而不是照搬人物 2:3；具体输出比例/像素待 `gpt-image-2` 实测。

以上未获得创作者确认前，不能写入正式产品决策或作为 Codex 不可变需求。
