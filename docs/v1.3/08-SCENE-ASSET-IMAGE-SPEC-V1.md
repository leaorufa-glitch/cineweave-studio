## 1. 场景资产真正要解决的问题

美术场景不是“一张好看的背景图”，而是同一个虚构空间在不同镜头、时间、天气与表演条件下，仍有可信的地理结构、物件关系和影片视觉风格。第 2 区负责场景美术身份和空间基础，第 3 区决定导演怎么拍，第 4 区落实机位/分镜/视听时序，第 5 区按视频模型能力进行参考编译，第 6 区审查实际空间连续性。

- **艺术**：场景应服务题材、年代、人物处境、戏剧氛围和视觉叙事。
- **地理**：角色入口/出口、门、窗、主要建筑、道具、道路、桌椅等固定地标的**相对位置**要有共同依据。
- **视觉**：材质、比例、老化程度、主色、装饰、天气与灯光应与影片美术基线一致。
- **可生成**：正式图像确实存在且能审阅、能关联资产版本；目标视频模型能否有效引用需独立验证。
- **可修改**：修改场景设计时能追踪哪些 Scene/Shot/Clip/Take 可能受影响，而不删除历史成片素材。

## 2. 场景的正确业务层次（建议）

| 概念 | 表示什么 | 例子 |
|---|---|---|
| **Location Identity**（场所身份） | 故事中同一个物理地点 | 某一座小站台、某间客厅、同一条走廊 |
| **Set Design Revision**（空间/美术设计版本） | 固定的建筑轮廓、功能区、材质、陈设和关键地标 | 出口位于候车棚的一端、站牌/长凳/灯柱的位置 |
| **Environment Look / State**（环境视觉状态） | 同一地点的时间、天气、季节和主要灯光/布置状态 | 雨夜车站、晴天清晨车站、停电后的候车室 |
| **Reference Media**（真实参考媒体） | 同一场所/环境状态当前正式采用的**一张完整多视角宫格** | “雨夜车站多视角场景宫格”PNG |
| **Shot/Clip State**（镜头内状态） | 角色位置、运动、临时物件、当时天气瞬变和镜头光线要求 | 女儿站在长凳前，钥匙落在地上；雨正逐渐变大 |

**不能混淆**：同一地点的正反拍不是两个 Location；雨夜/白天也不自动是两个 Location。换照明不应重置建筑身份。剧情中真的换景、重建房屋或永久修改陈设时再评估新场所或新设计版本。

## 3. 已确认正式参考形式：场景统一多视角宫格

### 3.1 一个场所/环境状态，一个当前正式完整场景宫格

- 同一地点在同一正式环境状态下，采用**一张完整多视角宫格**，其中不同格子必须描述同一个物理空间、相同固定建筑及陈设的相容视角。
- 每个环境状态可以独立正式定型（如雨夜/白天），但都指向同一个 Location 身份和相容的建筑布局。
- 一个场景可以有多个候选宫格和历史修订，但同一场所/状态只保留一张**当前正式采用**的整图；历史生成输入与媒体引用保留。
- **不将宫格拆成若干分别正式管理的独立角度图**；第 3/4 区引用场所/环境状态/完整宫格版本。
- 主要场景与次要场景都按已确认的**完整多视角宫格形式**组织；可以后续讨论轻重不同的格数/信息密度，不能未经确认退回单张主图方案。
- 仍建议保存**精简空间事实说明**，记录固定入口/出口、地标、功能区的物理相对位置。不能因为宫格看着一致就把 AI 生成画面当成精确 3D 空间或真实地图。

### 3.2 宫格分层布局（已确认）与具体取景（可按空间调整）

| 宫格视角职责 | 提议展示什么 | 原因 |
|---|---|---|
| **上方大主视角**（Establishing） | 横跨整体宽度的主要场所参考画面，展示完整空间、美术气质、标志地标和主要行动区 | 提供权重最高的空间身份锚点 |
| **下方左：反向/对向**（Reverse） | 从物理可行的位置回望同一地点，地标相对位置保持一致 | 验证空间连续性，支持导演选机位 |
| **下方中：主要行动区**（Action Area） | 靠近门、长凳、桌边或真正有演员行动的地方 | 了解表演空间与人物调度 |
| **下方右：侧向补盲/连接区**（Side/Coverage） | 补主视角难呈现的一侧、转角、连接区或纵深 | 减少死角并校核建筑结构 |

**整体是一张完整图片，不拆四张正式单图**；主图显著大于每一幅辅助图，辅助图仍需清楚可辨。特殊空间可调整具体机位，但不得为了凑四格虚构空间。布局已确认，**上下高度分配、总体画幅、实际像素仍待图片模型实测**。

### 3.3 不要混淆“宫格资产”和“导演镜头”

宫格为**美术空间参考**：不同格子不是第 3 区已批准的 Director Shot，也不能直接当第 4 区的实际分镜或视频 Clip。导演仍决定何时切镜、机位、构图与叙事；分镜根据同一正式空间及导演 Shot 细化执行。画面中不必有正在表演的角色。

多角度准确性不能通过“生成一张多视角图”保证，必须在第 2 区审阅整张宫格中门窗、桌椅、出口、背景地标的共同逻辑；第 6 区再用真实 Take 复核。

## 4. 场景宫格内各视角的职责（待定模板）

| 视角职责 | 解决的问题 | 第 3/4 区如何使用 |
|---|---|---|
| 整体参考（Establishing） | 地点身份、尺度、陈设与美术方向 | 确定故事场所，不等于导演必须采用这个机位 |
| 反向与方位参考（Reverse/Direction） | 其他观看方向的固定地标及空间连续性 | 用于规划反打、转身或长镜头运动 |
| 行动空间（Action Area） | 人物在门口、长凳、桌边等区域的合理走位 | 支持调度和具体 Shot 的背景约束 |
| 细节/材质与状态（Detail/State） | 关键结构、材质以及本次环境状态 | 复核视觉风格与连续性 |

建议在整张图的资产描述里记录**上方主视角和下方三个视角的实际观察位置/大致朝向**，而不是增加四个正式媒体身份。**1+3 已确认；像素、精确画幅比例和细节 QA 仍待实测**。

## 5. 场景宫格的创作与正式定型

1. 从已采用剧本、世界设定与导演总体意图识别**同一个 Location**，明确其物理构造、固定地标与本次环境状态。
2. 美术 LLM 提出可审阅的多视角宫格创作提案，包括各格观察位置、它们应看到的共同固定物件、作品美术风格及时间天气状态。
3. 按已审定的宫格模板**产出一张完整场景多视角图**；可以由用户上传已有完整宫格或采用图片模型生成候选。每个候选保留真实媒体和来源。
4. 专业 AI 与用户对**整张宫格**做空间、材质、地标、环境状态和清晰度检查，发现某格结构错误时重修**同一宫格候选/版本**，不自动拆图入库。
5. 选用一张**当前正式整图**及其 Location/Environment 版本，保留以前候选及历史引用。不同天气/昼夜状态可以拥有不同正式宫格但共享同一 Location。
6. 第 3/4 区从场所和环境状态选择相应的**完整宫格**，再决定导演 Shot 与分镜，并检查某具体目标视频路由是否有效支持该类图板参考。
7. 第 5/6 区对真实生成请求与 Take 审查；如模型误将多视角拼图当作多场景、多机位或把人物复制，报告实际限制并返回设计，而不是伪称兼容。
8. 场景修改正式采纳后，通知引用旧宫格的计划待复核；历史 Run/Take 不被覆盖。

**尚需设计**：图片模型是否能一次稳定产生多角度一致性、图片分辨率是否足够、失败格子的修改方式、目标 H3 路由如何正确引用整张宫格。

## 6. 场景多视角宫格语义生成模板（待实测适配）

> 请为电影项目【Film】中的同一物理场所【Location】和环境状态【雨夜/白天等】生成**一张完整的多视角场景设计宫格**，不可输出几个彼此独立的正式参考文件。  
> 作品美术方向：【年代、材质、尺度、使用痕迹、整体视觉风格】。  
> 必须保持的物理事实：【入口、出口、窗、固定家具、关键地标及它们的相对位置】。  
> 采用**上 1 下 3**：上方一幅大场所主视角，下面从左到右依次是反向/对向、主要行动区、侧向补盲。分别呈现【各格观察点、主要朝向、应看到的地标】，所有格子必须属于**同一个真实可想象的空间**；同样的门、长凳、标牌和灯柱不得在不同格子中被任意发明或移动。  
> 保持【当前时间、天气、环境布置】在这一整张图中一致，不混合雨夜和晴天等不同 Look。  
> 默认不要添加表演人物、随机剧情动作、与空间事实冲突的额外建筑或道具，也不要把多视角当成多个独立的电影 Shot。  
> 输出**一张完整的多视角宫格资产**，供创作者审阅与后续合法引用；该图不是实际影片帧。

**说明**：上述是业务级语义模板，不是已验证的 `gpt-image-2` 请求体。宫格的具体格数、画幅、输出清晰度、能否参考旧场景进行准确变体、视频模型能否直接有效利用整图都必须独立核实，未验证时不能声明其必然可用。

## 7. 场景图 QA 验收

| ID | 验收点 | 不合格例子 |
|---|---|---|
| SC-01 | 有明确 Location 身份与对应 Scene/世界设定 | 只叫“漂亮街道”，不能判断与故事哪个地点对应 |
| SC-02 | 主要美术风格、时代、材质与剧本/导演意图一致 | 故事中的旧车站被生成成全新未来科幻站 |
| SC-03 | 固定空间地标相对关系可理解 | 正反机位中楼梯、出口和长凳的空间关系自相矛盾 |
| SC-04 | **一张完整宫格**是真实可访问、可预览、来源可追踪的媒体 | 只有文字提示词，或系统将四个格子自动登记成四张正式参考图 |
| SC-05 | 环境状态与地点身份分开 | 仅仅下雨就误建成另一个“新车站”身份 |
| SC-06 | 同一宫格各视角相互符合空间与材质事实 | 右上反打格突然多出第二个大门，建筑风格改变 |
| SC-07 | 能理解整张宫格及各格的实际视角职责 | 四格代表四个不同地点，用户不知它们如何对应 |
| SC-08 | 引用已确认版本并能追踪影响 | 场景换版后，历史 Run 的参考文件被静默改写 |
| SC-09 | 第 4/5 区只使用目标模式真实支持的整图引用 | 未验证视频模型能否理解宫格，就声称每格均被准确使用 |
| SC-10 | 不以多视角宫格替代真实成片验证 | 视频生成后空间断裂，系统却因宫格 QA 通过宣布镜头连续性通过 |

技术质量需实测输出的真实比例、像素、清晰度及生成接口，不在本文编造固定尺寸或能力上限。

## 8. 80 秒案例：雨夜车站

**场所**：同一个小站台。资产设计先建立“雨夜车站”的**一张完整多视角宫格**，每格从不同方向展示同一候车棚、出口、长凳、照明和站牌等主要地标；同时在空间事实中记录它们的**物理相对关系**。环境状态为“雨夜”。

导演希望在 Shot04 保持父女站位距离与镜头连续，因此可能需要确认：人物站立位置、行动区可活动宽度、雨夜反光与车站固定物件在 B1/B2 中是否保持可信。第 4 区可以请求行动区参考；第 5 区若采取原生续接，仍以真实上游 Take/Motion Context 为依据，**不把场景图误当作原生续接上下文**。

若 B1 与 B2 的生成结果出现“同一候车棚两次出现完全不同的大门”，审片可以根据真实视频和地点美术事实判断需修订场景参考、分镜约束还是视频生成策略。

## 10. 已确认的“上 1 下 3”场景图板与细节草案

> **用户方向已确认**：由用户提出“是否可以1+3，主视角大一点，下面三个辅助视角呢？”，讨论后要求继续下一步。**上方一个大主视角，下方三个辅助视角**作为场景参考正式布局；**不是等大 2×2，也不自动继承人物图的 2:3 竖幅**。具体画幅、像素和模型契约仍待审定或真实验证。

### 10.1 版式与视觉职责

| 区域 | 已确认职责 | 详细执行建议（待审定） |
|---|---|---|
| **上方主图（大）** | 场所主要身份、空间整体、主行动区及美术气质 | 从物理合理的代表性位置看向关键地标；确保主体足够清楚，不只做氛围空镜 |
| **下方左（辅助一）** | 反向/对向视角 | 从可拍摄位置回望同一空间；不必数学上精确 180°，但不能靠穿墙获得“反打” |
| **下方中（辅助二）** | 主要行动区 | 交代门口、桌边、站台等表演实际发生处与可行路径 |
| **下方右（辅助三）** | 侧向、补盲或连接区 | 揭示其他视角看不到但与镜头规划相关的结构及地标 |

**整体仅保存一张当前正式采用宫格图片**，不拆成四张独立正式资产；三幅辅助图片不是剧情顺序里的三个 Shot。特殊狭窄空间可灵活确定**合理观察点**，不能为达到图板形式强行虚构建筑结构。

### 10.2 简洁空间事实与生成输入

创作者和美术 AI 在生成前需要能够表述：**Location 身份、设计版本、本次昼夜/天气环境状态、一个基准观察朝向、3–5 个关键固定地标及它们的相对位置、四幅画面的实际观察方向**。3–5 是便于启动的建议数量，不是硬编码限制。

例如：雨夜车站拥有一条明确的铁轨方向，候车棚、出口、站牌和长凳的位置须在四幅画面里保持物理协调。角度转换后屏幕左右变化、物件因遮挡而不可见，都不属于矛盾；某个出入口突然消失或凭空新增则可能是严重错误。

### 10.3 一张完整图板的生成模板（语义级草案）

> 请为【影片名称】中的【场所 Location、正式设计版本、当前环境状态】生成**一张完整的上 1 下 3 多视角场景宫格**。上方是宽阔、清晰、占视觉主体的**场所主视角大图**；下方并排三张尺寸较小但细节可识别的辅助图，分别是**反向/对向视角、关键行动区域视角、侧向补盲/连接区视角**。四幅画面必须属于**同一个物理场所、同一空间结构、相同天气与时间状态**，服从【空间事实、主要建筑和地标位置、材质年代、美术风格】。
>
> 四个观察点均应在物理上合理，从不同方向呈现同一地点；不能额外添加主要门窗、道路、建筑或固定家具，也不能让建筑结构、地标大小和材质互相矛盾。不同角度下可自然遮挡或出画。默认不加入演员、剧情动作、复杂图中文字及宣传标识。只输出**一张完整整合图板**，不是四个互相独立的场景，也不是四个连续电影镜头。

生成后审核真实整图，**不能仅因为 Prompt 写了这些约束就宣布空间一致性已实现**。

### 10.4 必须分别验收三个环节

1. **静态宫格本身**：一张文件、1+3 布局、主图大、辅图细节可辨；同一场所/同一环境状态；地标/材质/物理空间逻辑可核对。**重要地标与空间连通性矛盾时不得正式采纳**。
2. **图片模型能力**：当前 gpt-image-2 中转路由是否能稳定生成布局与跨视角一致性，支持什么长宽比、参考图/重修能力，需依真实模式验证；不能编造能力。
3. **视频模型能力及真实 Take**：H3 当前具体路由是否能合法引用和正确解释整张图板，以及生成片段是否空间连贯，都要由第 5/6 区据真实调用与播放结果判断。

### 10.5 尚需细化（不推翻已确认的 1+3）

- 具体整图宽高比与像素、上方主图占高度多少、底部图最小可读尺寸；
- 根据室内、室外、狭窄场所调整辅助视角的取景建议；
- 宫格有一格出错时如何修订整张正式候选且不损坏其他正确视角；
- 存储一张完整图板的技术格式和元信息，及不同模型对复合图板的实际理解能力；
- 输出人物/临时道具、虚构地标、空间结构不一致的质量拒用标准与人工覆核边界。
