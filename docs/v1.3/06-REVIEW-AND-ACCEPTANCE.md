# V1.3-06｜设计决策清单与专业能力验收

> **状态：草案 / 审阅提纲，尚未通过**  
> 日期：2026-10-10  
> 本文用于把 V1.3 的重大设计选择显式提出来，避免编程 Agent 自行把草案转成产品决定。  
> **本轮按要求不生成或修改关系图、架构效果图或 UI 效果图。**

## 1. 已确认的基础，不能被新草案覆盖

| 已确认决定 | V1.3 的具体体现 |
|---|---|
| 六大工作区对最终质量都重要 | AI 专业能力和审查在六区全部深入开展，不刻意压缩第 1 或第 6 区 |
| 故事与剧本是创作原点 | 第 1 区拥有正式剧作引擎：人物、戏剧、因果、对白与反复改稿 |
| LLM 贯穿全部六区 | 各区都能进行专业创作、分析、比较、审查和跨区反馈 |
| 统一影视工程与确定性系统管理 | 上下文、事实版本、候选、采纳、依赖和生成状态都交给系统管理 |
| 第 3 区创建 Shot，第 4 区细化同一 Shot | 一个身份，导演决定镜头语言；分镜落实视听执行计划 |
| Shot 不等于 Generation Clip | 支持多 Shot 合一 Clip、一个长 Shot 拆多 Clip |
| H3 主力、V1 单次 Clip ≤15s | 编译和生成前校验，超过上限的导演长镜头须评估分段策略 |
| 续接依赖真实父 Run/Take 与 Motion Context | 只有真实可用上下文的合法任务才称为原生续接 |
| 使用既有聚合站 | 不重建中转站，模型特有能力、请求合法性仍需分别管理 |

V1.2 的详细对象、权限和工作机制仍是**草案**；本 V1.3 建议依赖于这些草案，如 V1.2 有调整必须同步复核。

## 2. 应当审阅的产品选择（目前不自动决定）

| 编号 | 要定的问题 | 本次推荐默认方向 | 决策影响 |
|---|---|---|---|
| D-01 | 用户和 AI 如何共同写剧本？ | 用户可在“共同创作 / AI 初稿 / 现有剧本优化”之间切换；默认共同创作 | 第 1 区主界面、版本和协作交互 |
| D-02 | 要不要每个工作区设置强制审批门？ | **不推荐**；重要创作更改和实际成本才需显式或预先授权 | UX 摩擦、自动推进能力 |
| D-03 | 是否固定“六位大师 Agent”？ | **不推荐**把人数定死；按专业任务与效果配置 LLM 能力 | 智能编排和系统复杂度 |
| D-04 | AI 诊断如何被采用？ | 保留证据 + 候选差异 + 决策记录；不直接覆盖正式数据 | 长期一致性、回溯与返工 |
| D-05 | V1 是否支持系列/多集？ | 保留必要的 Project / Film / 资产共享关系，多集深度编排分阶段扩展 | 对象模型与导航 |
| D-06 | Clip 模型选择谁决定？ | 第 4 区提出适用策略，第 5 区合法编译执行；高成本模型需用户授权 | 导演自由、费用与风险 |
| D-07 | 视频质量检查由谁完成？ | 系统技术校验 + 专业 LLM/多模态审看 + 用户选择相结合 | 第 5/6 区产出与验收 |
| D-08 | 何时自动推进连续生成？ | 仅在真实父 Take 和上下文合格、且有明确预授权时自动进行 | DAG 等待、用户负担与成本 |
| D-09 | 第 6 区轻量后期的边界 | 支持选 Take、裁剪、基本声画衔接、时间线、渲染；不追求替代专业 NLE | 第一版工程范围 |
| D-10 | 高保真 UI 何时开始？ | V1.2/V1.3 专业流程与核心对象审阅后，先交互原型再视觉 | 避免重复返工 UI |

以上是**建议，不代表用户已逐条审定**。如果创作者同意总体方向，可作为后续详细 UX 和 Codex 开发任务的依据；若有异议，应修订对应文档。

## 4. 以 80 秒短片检查 V1.3

继续使用 [V1.2 80 秒端到端案例](../v1.2/04-ACCEPTANCE-SCENARIOS.md) 作为设计检验，不代表该故事或影片本身已经实际完成。

| 阶段 | 必须满足的表现 |
|---|---|
| 第 1 区剧本 | AI 能发现人物和解缺少铺垫，提出具体情节修订及人物动机依据 |
| 第 2 区资产 | 角色形象/服装、人声、场景与钥匙道具具备真实文件和正式版本 |
| 第 3 区导演 | Shot04 22 秒不切镜由导演决定，理由是保留空间关系与表演停顿 |
| 第 4 区分镜 | 同一个 Shot04 细化为 B1 12s + B2 10s，音画事件、参考和状态明确 |
| 第 5 区生成 | A1 可同时含多个 Shot；独立 Clip 可并发；B2 等待合格 B1 父 Take 与真实 Motion Context |
| 第 6 区审片 | 以真实媒体判断对白、表演、钥匙在哪只手、情绪转折和可剪辑性 |
| 跨区返工 | 若需补写情节，更新剧本并定位受影响的导演/Clip；保留旧 Take |
| 成片交付 | 采用 Take 的区间形成非破坏性 Timeline，Render 是真实可播放文件 |

## 5. 第一版工程最终不得出现的错误

- 将第 1 区简化为“AI 一键生成故事”，只检查输出格式是否完整。
- 将 LLM 限制在某几个步骤或单独的聊天页面，而非贯穿所有工作区。
- 分镜再创建第二套与导演 Shot 无关联的镜头 ID。
- 把每个 Shot 强行变为一个 Clip，或把一个导演长镜头切开就当成两个导演 Shot。
- 一条续接任务在没有真实父 Run/Take 或 Motion Context 时也被标为可原生续接。
- 异步视频任务丢失或超时后盲重试，引起重复生成费用。
- 视频任务返回成功后未看过实际视频/音频就判定“作品通过”。
- 用户改变人物/故事/Shot 版本时，旧编译任务继续被假装为最新方案。
- 为了“减少后期”取消必要的选 Take、节奏、声音衔接或成片验证。
- AI 擅自删除或覆盖正式工程历史，系统无法溯源已生成媒体。

## 6. 本阶段完成的定义

当前仅将以上规则整理为**专业创作与影视生产机制草案**。设计可以认为“具备审阅条件”，但不能宣称：

- V1.2/V1.3 已获最终批准；
- 已建立数据库、任务队列、媒体处理程序；
- H3/Seedance/Wan3 或文本/图片模型已完成联通测试；
- 已有可运行 UI、可播放生成片段或真实的成片；
- 已经开始或完成 Codex 工程实施。

在这些文档审阅后，下一步应细化 UX 交互契约和技术合同；**用户要求暂不生成关系视图的约束仍应遵守，直到另有明确请求**。
