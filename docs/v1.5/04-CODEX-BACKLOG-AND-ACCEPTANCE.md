## 0. 唯一推荐的施工原则

**先构建一条可持续交付真实影片的竖向闭环，而不是先把六区做成六个漂亮但没有真实功能的空页面。**

推荐技术候选：桌面优先 React/Next.js + TypeScript 的模块化 Web 应用，PostgreSQL 稳定事务，S3 兼容媒资，后台持久 Worker（优先 DB 队列），ffprobe/FFmpeg 实际媒体检查与 Render。具体 ORM/队列实现/部署环境由工程启动时确认；**用户还没有明确批准最终技术栈**。

**路由优先级（PD-010）**：**用户自有 H3 是正式生产主力**，自有服务器目前未开机；RunningHub 仅供临时/过渡测试，不是长期核心，适配它不是第一批或正式发布阻断项。开发用 Mock/已有合法测试媒体先推进，**无需催促用户开机**。Darl 公开“自部署”代理 API 不能直接等同用户自有 H3。见 [PD-010](../decisions/2026-10-11-H3-SELF-HOSTED-PRIORITY.md)。

下面按 Task ID 排序。只有当前序号依赖已经通过验收的模块才能进入下一真实演示；可并行开发的基础模块不必机械按剧本顺序交付。

## 1. 每个 Codex 任务的统一交付格式

每个 task 的 Pull Request 必须包含：

1. **产品行为**：对应第几区、解决哪个创作者工作、不变量引用、预期可见结果；
2. **实现边界**：涉及的模块、数据迁移、API、Worker、媒体或实际供应商模式；
3. **可运行证据**：本地使用方法、测试命令、Mock 数据、成功/失败案例及实际截图/可播放结果（若适用）；
4. **测试**：类型/单元、Postgres/对象存储集成、Provider 请求响应 Fixture、必要真实视频元数据/Render 测试，及用户操作路径；
5. **来源**：数据/资产的 Revision、Run、Take、Render，不允许只保存当前“最新”一条；
6. **明确限制**：未连接、未实测、权限不支持的模式显示禁用/待验证，不使用假成功界面；
7. **安全与成本**：不得提交密钥；付费调用必须受明确预算授权；提交未知不能自动重复扣费。

**DoD（完成定义）**：可操作 + 有真实保存/返回结果 + 可复现测试 + 失败路径处理 + 文档与结果一致。不能仅靠页面静态图、控制台打印“Success”或一个模型回答“已实现”。

## 3. 独立实测门槛：哪些事不得用 Mock 冒充

| 测试 Gate | 为什么必须真实验证 | 没过怎么办 |
|---|---|---|
| **G1 资产生成** | 人物 2×2，场景/道具 1+3 是否真的按格生成、跨格身份和几何是否协调 | 图片资产质量仍标“待验证”，可以做导入和手工审核，不能声称 AI 自动生成稳定 |
| **G2 复合图板给 H3** | 模型是否将一张多视角图板理解为同一人物/空间/道具，而不是四个人/四镜头 | 给出风险提示、转合法模式与经创作审阅的执行策略，不擅自拆四个正式资产 |
| **G3 原生音画和语速** | 实际生成是否有可听台词/环境声、声音身份及语速符合导演要求 | UI 显示能力限制，用真实 Take 审听，必要时专业修改 |
| **G4 真续接** | 必须有真实父 Take、Context、合法模型和实际续接样片 | CW-11 阻断但其余任务可继续，不用尾帧或二采冒充 |
| **G5 成片** | MP4/音轨真实可用、整片时长/字幕/基本声音衔接与媒体出处准确 | Render 未通过 QC 就不显示可交付 |

G1～G4 涉及实际收费模型时必须得到**单独明确预算/执行授权**；G5 可以用无付费的用户授权素材或 Mock 视频进行技术验证。

## 4. 现阶段还需要确认的三件事

1. **工程启动授权**：用户是否允许开始 CW-00～CW-02 的**非付费**代码/数据库/页面开发；“继续讨论设计”不自动代表启动。
2. **技术方向认可**：推荐模块化单体 Web + Postgres + S3 存储 + 持久 Worker + FFmpeg，若有部署资源约束可以在开始之前指出。
3. **自有 H3 联调条件**：服务器目前未开机，**现在不需要为开发而开机**。等联调阶段再核实自有服务的真实接口路径、Motion Context 父上下文产生/消费方式、鉴权方式（密钥不入仓库）及脱敏成功样例。没有这些也继续推进 CW-00～CW-05、Mock 审片与导出，不把 RunningHub 当成永久替代。

**不再要求创作者逐个批准 12 个任务**。集中批准第一批施工及边界后，后续依验收结果持续推进；任何收费任务另行授权。
