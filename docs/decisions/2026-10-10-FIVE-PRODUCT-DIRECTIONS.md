## 已批准的产品方向

| 决策 ID | 正式决定 | 适用范围 | 已确认边界 |
|---|---|---|---|
| **PD-001 / R-01** | 第 1 区默认**AI 深度共创**；同时提供**AI 主导初稿**和**导入已有剧本并优化**，项目内允许切换方式 | 前期创作及全局 AI 协作入口 | 剧本与故事是作品原点；不把编剧能力弱化为一键生成 |
| **PD-002 / R-02** | **专业 LLM 贯穿全部六区**，依据当前工作区和真实影视工程上下文提供专业创作、建议、诊断与跨区反馈；不预设固定六个独立 Agent | 全局智能协作与上下文 | 正式事实、版本、授权与执行状态由系统持有 |
| **PD-003 / R-03** | 普通创作候选和常规细化应可顺畅自动推进；**重要故事/导演决定以及实际生成费用**通过用户明确操作或有效预先授权策略管理；**不设置六区强制通关审批门** | 全局方案采纳、任务执行、成本控制 | 具体权限分类、默认预算与 UI 确认行为仍需设计和验收 |
| **PD-004 / R-04** | V1 具备基础 **Project / Film(Episode)** 及人物、世界设定、资产共享能力；复杂全季自动化编排暂不纳入第一版 | 项目导航、跨集事实及资产版本 | 具体 Series 导航、创建流程和资源作用域仍是交互设计细节 |
| **PD-005 / R-05** | 第 6 区保持**轻量后期操作**，必须支持播放器、Take 对比与选用、选段、基础非破坏性时间线、必要声音衔接、真实渲染导出和跨区返工；不做完整专业 NLE | 审片与成片 | “轻量”不是省略真实音画审查或剪辑判断 |

## 与 V1.1 基线的关系

此决策**补充而非替换** V1.1 已确认的产品总体架构：
- 六大工作区共同负责作品质量；第 1 区的故事/剧本不可弱化；
- Director Shot 由第 3 区建立，第 4 区细化**同一个 Shot**；
- Shot / Generation Clip / Run / Take / Timeline Segment 分别建模；
- H3 主力，V1 单次 Clip 上限 15 秒；原生续接绑定真实父 Run/Take 及 Motion Context；
- 全部模型使用已有聚合中转站，具体模式与路由能力按事实验证。

## 决策实施影响

- **V1.4 UI/UX** 以六区专业工作与跨区创作体验为目标，重点处理第 1 区真实剧本共创、贯穿六区的 LLM 体验、候选采纳与历史、Shot 同一身份、实际生成与续接链、Take/Timeline。
- **V1.5 工程实施** 必须把五项作为正式产品要求，不能由 Codex 自行更换默认编剧模式、强加审批门、硬编码六个 Agent 或删去必要的成片能力。
- **旧文档状态**：`docs/v1.2/`、`docs/v1.3/` 其他内容仍为草案，尤其 AI 工作合同细节、数据字段、权限状态、UI 结构、模型路由需要继续设计与评审。
- **设计材料**：根据用户最近要求，**暂不生成或更新关系视图**；可以先编写六区文字交互规范。
- **开发范围**：本决策并未授权开始应用代码开发或运行收费模型生成。
