# PD-010｜自有 H3 是正式主力；RunningHub 仅作过渡测试

> **状态：用户明确确认的工程与模型路由优先级；2026-10-11（北京时间）**  
> 来源：用户明确说明“RunningHub 的 H3 只是测试阶段用，后续主要还是用自有的 H3 模型，不必过于纠结，只是现在服务器未开机而已。”

## 已确认的事实与决定

1. **用户自有 H3 模型服务是本项目的长期、生产优先视频生成引擎**。专业影视生产、Clip、原生音画、参考资产和原生 Motion Context 续接的设计，均应以能适配用户自有 H3 为主要目标。
2. **RunningHub H3 仅是自有服务器未开机时的临时测试/过渡通道**，不是与自有 H3 平级的长期核心生产方案；它的公开网关限制不应决定产品上限、领域模型或工程优先级。
3. **当前自有 H3 服务器尚未开机**。这是暂时的联调可用性问题，**不是功能被否定、项目必须切换长期路线或要求创作者立刻开机**。
4. 可以继续完成**不依赖在线自有服务器**的产品/开发工作，包括 Mock 模型、影视工程、图板媒资、导演 Shot/Clip、任务队列、模拟 Provider、审片/导出。实际与自有 H3 联调在服务器可用且用户授权后进行。
5. **自有 H3 的真实接口合同仍需读取其实际部署文档或实现**。不能因为 Darl 文档写有“MiniMax-H3 自部署渠道”就断言该公开代理协议等于用户自有 H3 的实际 HTTP API、上传模式、费用、状态、音画或续接协议。
6. 用户此前已报告自有 H3 原生续接能力已实现；工程设计要给它保留**一等能力位置**。在当前服务器未开机且未取得可执行 API 资料时，可标记“等待联调验证”，**不应误写为用户不具备该功能**，也不能把尾帧、视频参考或二次采样冒充实际原生续接。
7. RunningHub Adapter 如有助于测试可保持**可选、低投入、非首发阻断**；对其适配不应该成为自有 H3 开发、Clip/Take/审片闭环或整片导出的必经前置条件。任何真实付费网关调用仍需单独授权。

## 修正后的实施优先级

1. **第一优先**：共享影视领域模型、可靠媒体与正式版本、专业 AI、导演 Shot 与 Clip、持久 Worker、可播放 Take、轻时间线/Render；使用 Mock 和导入测试素材推进，无须服务器开机。
2. **第二优先**：面向**用户自有 H3**的可插拔 ProviderAdapter、能力声明与真 Motion Context 续接所需身份和依赖合同；待服务器可用后以实际协议/真实素材联调并验收。
3. **第三优先（按需）**：RunningHub 用于有帮助的阶段性测试；不为两套代理路由的所有边缘特性耗费主要研发时间或阻止主路线完成。

**设计不变量**：单次 Generation Clip ≤15 秒（项目当前第一阶段规则）；Shot 与 Clip 多对多；人物 2×2 完整宫格、场景/关键道具 1+3 整板；真实音画、Run/Take、续接/二采区分、审片/成片均不因临时测试服务限制而改变。

## 证据界限

- **已由用户确认**：自有 H3 为长期主力、RunningHub 临时测试、服务器当前未开机、此前报告自有原生续接已实现。
- **尚未由当前工程实测**：自有服务器的确切 API 路径/参数、当前上线状态、具体 Motion Context 传递方式、真实生成质量、运营成本；这些应在开机联调时以真实记录确认。
- **仅为外部文档资料**：Darl 的 MiniMax-H3 自部署渠道与 RunningHub 公开 API 文档，不等同于自有 H3 的运行接口。
