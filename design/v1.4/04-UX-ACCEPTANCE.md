# V1.4-04｜交互验收清单与待审定 UX 设计细节

> **状态：UX 草案，待创作者审定**；日期：2026-10-10  
> **正式依据**：V1.1 已确认架构 + 2026-10-10 五项正式产品方向。  
> **注意**：此处的“验收”是**未来原型应通过的行为标准**，不代表网页、交互原型或应用已经实现或测试通过。

## 1. UI/UX 应如何按优先级完成

**先文字交互契约**：当前四份设计文件回答六区的页面信息、动作、AI 行为、状态和跨区关系。

**再低保真原型**：六区都需具备主要功能流；第 1 区以剧本深度共创为重点，第 3/4 区以导演 Shot 和生成规划为重点，第 5 区以可靠生产状态为重点，第 6 区以实际审片为重点。不要因为“第 3/4 区技术更复杂”而弱化其他工作区的专业重要性。

**随后高保真 UI**：在创作者认可操作方式后，统一视觉语言、桌面版密度、组件、可读性、快捷操作、状态/加载/失败表现，制作核心场景效果图。

**最终工程交接**：将被批准的交互映射到数据、API、权限、后台状态和可验证测试，再交付 Codex 实现；不要让 Codex 重新决定产品业务语义。

目前用户要求**暂不生成或更新关系视图**，所以本阶段先做文字规格；制作低/高保真原型需要等后续单独确认或明确启动。

## 2. UX 必须通过的业务验收

| ID | 用户任务 | 第一版原型必须能表现的结果 |
|---|---|---|
| UX-01 | 创建作品并选择创作路径 | 默认 AI 深度共创，可切换 AI 初稿/已有剧本优化；能够创建 Film |
| UX-02 | 真正改写某场戏 | 用户能直接编辑 Scene/Beat 与对白，AI 提供不同戏剧方向和证据 |
| UX-03 | 保留剧本候选和正式版本 | 用户能区分提案、工作草案、正式采纳和历史差异 |
| UX-04 | 跨区专业 AI | 六区均有基于当前对象/版本的 AI 协作，不是六个孤立聊天记录 |
| UX-05 | 真实资产管理 | 人物/场景/声音身份、采用版本、实际媒体文件、参考职责可见 |
| UX-06 | 导演创建 Shot | 第 3 区能记录真实导演意图、人物/镜头/声音要求和 Shot ID |
| UX-07 | 分镜完善同一 Shot | 第 4 区使用同一 Shot 身份且能定位原导演意图，不重复建镜头 |
| UX-08 | 一个 Clip 两个 Shot | 12 秒 Clip 可以清楚显示并编辑两个 Shot 的实际计划区间 |
| UX-09 | 一个长 Shot 两个 Clip | 22 秒不切镜可以规划两个 Clip；明确分段生产≠新增导演切镜 |
| UX-10 | 真实多模态参考绑定 | 第 4/5 区能定位资产版本、真实文件和用途，缺失时说明修复方式 |
| UX-11 | 模型合法编译与费用确认 | 第 5 区能展示模型/模式、输入检查、预计费用或未知提示与授权 |
| UX-12 | 异步批量生成 | 独立任务可并行；等待父 Take 的续接任务显示明确依赖原因 |
| UX-13 | 原生续接真实父链 | 有父 Run/Take 与 Motion Context 才可标记真实续接可执行 |
| UX-14 | 更换父 Take | 明确显示旧子链来源于哪个 Take，并提供保留/重续接的选择 |
| UX-15 | Take 成功不等于可用 | 可以实际播放、审查、选择或拒用媒体，并记录专业原因 |
| UX-16 | 非破坏性时间线与 Render | Take 源媒体不被裁剪覆盖，支持必要声画衔接和实际导出 |
| UX-17 | 剧本修改导致下游待复核 | 用户可查看影响和跨区跳转；历史媒体仍可回看 |
| UX-18 | 审片定位回编剧/导演 | 真实影片时间码和问题证据可以传回关联 Scene/Shot，支持定点返工 |
| UX-19 | 系列的第二集 | 能创建基础新 Episode，并引用已采用的人物/资产版本 |
| UX-20 | 从中途进入 | 用户有现成剧本、图片或真实视频时不被迫重走所有前置阶段 |
| UX-21 | 声音身份和语速独立 | 第 2 区能编辑角色基准语速/试听基础样音；第 3/4 区可以按句覆盖语速并单独设置停顿；第 5/6 区可核对实际模型能力与真实声音 |
| UX-22 | 场景统一多视角宫格 | 同一场所/环境状态对应一张当前正式完整多视角宫格；用户能查看格内空间一致性并将整图引用到 Shot/Clip，不自动拆分为多个正式媒体 |

以上是**设计验收用例**；正式应用验收还需要真实媒体、任务调度、数据库和实际模型测试。

## 3. 专业 AI 交互的质量判定

AI 界面不能只“看起来智能”，还需要：

- 第 1 区：提出有戏剧实质差异的故事方案，诊断具体 Scene/Beat 的人物动机、冲突和因果。
- 第 2 区：能根据真实剧本与导演方向解释选用哪些素材、为什么缺少某类参考。
- 第 3 区：能说清镜头选择服务什么表演、情绪、观众信息和叙事。
- 第 4 区：能把导演意图具体化为画面、动作、对白、声音与时间计划，而不是泛泛的“电影质感”。
- 第 5 区：能正确识别真实生成请求、模型模式和已生成媒体；不能对未观看视频声称已做 QA。
- 第 6 区：能附着实际媒体的时间码和相关剧本/Shot 解释问题，区分剧作、导演、分镜、生成与剪辑根因。

专业 AI 判断可能不同，界面要能保留候选、比较依据、用户改写和纠正错误诊断；不能机械地靠一个总评分决定是否允许下一步。

## 4. 桌面操作应满足的基本可用性

| 类别 | 要求 |
|---|---|
| 可理解性 | 用户不懂内部技术对象也知道当前正处于“剧本草案/导演镜头/生成 Clip/实际 Take”的哪一个层级 |
| 导航 | 六区随时切换，跨区引用可点击返回来源，回到原位时尽量恢复选中对象 |
| 密度 | 剧本页面以写作为主；导演以场面表达为主；分镜以画面与音画时序为主；审片以真实播放器为主 |
| 状态 | 重要任务显示“准备/等待/运行/完成/审片通过/失败/待复核”，不使用含糊的统一成功标签 |
| 修改 | 能清楚看到差异与受影响对象，普通操作不被多层确认弹窗拖慢 |
| 恢复 | 历史内容、源媒体与已发生的 Run/Take 不被界面操作默默删除 |
| 反馈 | AI 生成或模型任务异步执行时，用户能继续其他工作而不丢结果 |
| 可访问 | 文本对比不能只用颜色区分；关键按钮、状态与时间信息应有可读标签和可操作焦点 |
| 保密与凭据 | 即使仓库公开，页面也不应把实际密钥写入可被任意访问的前端源码或屏幕默认展示 |

## 5. 尚未决定、需要通过原型测试的 UX 细节

这些**不是**已确认新产品方向，不影响前面已批准的 R-01～R-05：

| 待定项 | 可比较的方向 | 判断依据 |
|---|---|---|
| 首次进入项目后的默认页面 | 作品总览 / 最近编辑工作区 / 剧本创作入口 | 是否减少开始工作所需操作 |
| 专业 AI 的具体界面位置 | 侧边可收纳面板 / 内嵌提案 / 按对象快捷动作；允许混合 | 是否帮助创作，而不遮挡剧本或视频 |
| 第 1 区故事结构与剧本如何切换 | 一屏分区 / 标签页 / 专注写作模式 | 是否便利地掌握全局又能专心写作 |
| 第 3/4 区同 Shot 的操作位置 | 双工作区共用 Shot 编辑实体、不同专业视图 | 是否避免重复数据和误解 |
| Clip 规划的时间交互 | 卡片区间 / 时间轴 / 两者互补 | 多 Shot 合 Clip 与长 Shot 拆 Clip 哪种最直观 |
| 审片 Take 对比模式 | 并排对比 / 快速切换 / 对比当前片段区间 | 真实表演与声音是否容易检查 |
| 版本历史的显示颗粒度 | 每次编辑版本 / 可命名里程碑 + 日常草稿 | 是否兼顾恢复能力与认知负担 |
| 多集 Project 的导航 | Project 内 Film 选择 / 可选 Series 视图 | 是否让独立短片用户保持简单 |
| 是否优先做响应式移动操作 | PC 为主，手机做轻查看 / 审批 | 初期用户真实操作环境与研发成本 |

每个选择应通过可操作的低保真交互和 80 秒短片用户场景验证，不应只凭一张漂亮图就确定。

## 6. 当前 V1.4 的阶段完成状态

**本轮已经有**：纯文字的全局交互原则、六区交互规格、跨区实际操作场景、UX 验收用例。

**尚未有**：创作者对本轮 UX 草案的批准、选定页面布局、低保真可点击原型、高保真 UI、真实应用页面、用户可用性测试或生成媒体测试。

因此，本阶段可以称为**V1.4 首轮文字交互设计已形成草案**，不能称为“V1.4 已验收完毕”。

下一步建议先让创作者审查三类高价值操作：**第 1 区编剧深度共创、第 3→4 区 Shot/Clip 合作、第 5→6 区生成/审片返工**。确认方向后才制作可视化原型。

用户要求的“关系视图先不生成”仍然有效。
