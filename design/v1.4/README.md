## 不可改变的设计底线

- 六区都是专业重要工作区；第 1 区不能变成只写一句提示词的“生成剧本”。
- **专业 LLM 在全部六区持续参与**，而不是只有一个聊天页或六个互相隔绝的机器人。
- 六区共享一个有版本的影视工程，而不是把内容在页面之间复制粘贴。
- **Director Shot 只有一套身份**：第 3 区决定，第 4 区细化。
- Shot、Clip、Run、Take、Timeline 各自可被用户理解和追溯，不能为了界面简单而混淆。
- 独立任务可以并发，原生续接的真实父 Take 与 Motion Context 必须可核对。
- 第 6 区轻量，但实际审片、选择源视频片段、声音衔接与真实成片不可省。
- 不要求六个强制审批关卡；按创作重要性、权限和实际生成费用决定必要确认。
- 首期以专业桌面浏览器为主要操作环境（交互设计建议，非已批准技术要求）。

## 本次明确不做

- **按用户要求，暂不生成/修改关系视图、产品架构图或其他新的关系可视化。**
- 不生成新的 UI 效果图或代码原型；它们在交互规则和关键场景审阅后安排。
- 不建立前端、后端、数据库、任务队列或应用脚手架。
- 不调用收费视频模型，也不对未实际验证的 H3 模式做兼容性承诺。

## 后续交付顺序

1. **第一轮（当前）**：审阅本目录的纯文字交互规格和跨区场景。
2. **第二轮（获准后）**：依照选定的交互，制作六区低保真原型；先校验操作，再确定视觉方向。
3. **第三轮**：定专业桌面 UI 设计系统、关键页面高保真效果与状态，核对真正可用。
4. **第四轮**：将批准的 UX 规则写入 V1.5 Codex 可执行的页面/状态/API 与验收合同。

所有新设计建议都保持**草案**，直到创作者明确审定。
